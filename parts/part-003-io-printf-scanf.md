## 3.1 ทบทวนและขยายความ printf: Format Specifier พื้นฐาน (Step 17)

`printf` เป็นฟังก์ชัน **Variadic** (รับพารามิเตอร์จำนวนไม่แน่นอน) ที่ประกาศอยู่ใน
`<stdio.h>` หัวใจสำคัญของมันคือ **Format String** ซึ่งเป็นข้อความที่มี "ช่อง" (Format
Specifier) ขึ้นต้นด้วย `%` แทรกอยู่ — compiler และ runtime ไม่ได้ตรวจสอบให้อัตโนมัติว่า
ชนิดของตัวแปรที่ส่งเข้าไปตรงกับ specifier หรือไม่ (เป็นหน้าที่ของโปรแกรมเมอร์ทั้งหมด)
แต่ gcc มี **Format Checking** ในตัว (เปิดใช้งานอัตโนมัติเมื่อเปิด `-Wall`) ที่จะเตือนทันที
ถ้าชนิดไม่ตรงกัน

| Specifier | ชนิดข้อมูลที่ใช้คู่กัน | ตัวอย่าง |
|---|---|---|
| `%d` / `%i` | `int` (จำนวนเต็มมีเครื่องหมาย) | `printf("%d", 42);` |
| `%u` | `unsigned int` | `printf("%u", 42u);` |
| `%f` | `double` (สำหรับ `float` จะถูก promote เป็น `double` อัตโนมัติเมื่อผ่าน `...` ของฟังก์ชัน variadic) | `printf("%f", 3.14);` |
| `%lf` | `double` — ใน `printf` (ไม่ใช่ `scanf`) `%lf` และ `%f` **ทำงานเหมือนกันทุกประการ** เพราะ C99 กำหนดให้ `l` ไม่มีผลกับ `printf("%f")` | `printf("%lf", 3.14);` |
| `%c` | `char` (หรือ `int` ที่ถูก promote) | `printf("%c", 'A');` |
| `%s` | `char *` (String แบบ null-terminated) | `printf("%s", "hello");` |

```c
/* printf_basics.c */
#include <stdio.h>

int main(void) {
    int    age = 25;
    double gpa = 3.75;
    char   grade = 'A';
    const char *name = "สมชาย";

    printf("ชื่อ: %s\n", name);
    printf("อายุ: %d ปี\n", age);
    printf("เกรดเฉลี่ย: %f\n", gpa);      /* default แสดงทศนิยม 6 ตำแหน่ง */
    printf("เกรดเฉลี่ย: %lf\n", gpa);     /* เหมือนกับ %f ทุกประการใน printf */
    printf("เกรดตัวอักษร: %c\n", grade);

    return 0;
}
```

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 printf_basics.c -o printf_basics
./printf_basics
```

> **ทำไม `%lf` ถึงใช้ได้กับ `printf` ทั้งที่บอกว่า "ไม่มีผล"?** เพราะมาตรฐาน C99 นิยาม
> `l` modifier คู่กับ `f`, `e`, `g` ไว้ว่า "ไม่มีผลต่อการแปลงค่าใน `printf`" (no effect)
> เพื่อให้นักพัฒนาที่คุ้นเคยกับ `scanf` (ซึ่ง `%lf` จำเป็นสำหรับ `double`) สามารถใช้ `%lf`
> ใน `printf` ได้โดยไม่ error แต่ในทางปฏิบัติ **ธรรมเนียมของ C คือใช้ `%f` เฉยๆ ใน `printf`
> เสมอ** และสงวน `%lf` ไว้เฉพาะ `scanf` เพื่อความชัดเจนและสม่ำเสมอของโค้ด

## 3.2 Format Specifier ขั้นสูง: เลขฐาน, Pointer และชนิดข้อมูลขนาดต่างๆ (Step 18)

```c
/* printf_advanced_specifiers.c */
#include <stdio.h>

int main(void) {
    int x = 255;

    printf("ทศนิยม (decimal) : %d\n", x);
    printf("เลขฐาน 16 (lower): %x\n", x);
    printf("เลขฐาน 16 (upper): %X\n", x);
    printf("เลขฐาน 8  (octal): %o\n", x);
    printf("เครื่องหมาย %%     : 100%%\n");

    int  n = 42;
    int *ptr = &n;
    printf("Address ของ n     : %p\n", (void *)ptr);

    long          l_val  = 123456789L;
    long long     ll_val = 123456789012345LL;
    unsigned long ul_val = 4000000000UL;
    size_t        sz_val = sizeof(int);

    printf("long              : %ld\n", l_val);
    printf("long long         : %lld\n", ll_val);
    printf("unsigned long     : %lu\n", ul_val);
    printf("size_t            : %zu\n", sz_val);

    return 0;
}
```

จุดที่ต้องระวังที่สุดในตารางนี้คือ **`%p`** — มาตรฐาน C กำหนดให้ต้อง cast argument เป็น
`void *` เสมอก่อนส่งให้ `%p` (`(void *)ptr`) เพราะ `%p` รับประกันว่าทำงานถูกต้องกับ `void *`
เท่านั้น การส่ง pointer ชนิดอื่นโดยไม่ cast (แม้ในทางปฏิบัติหลายแพลตฟอร์มจะทำงานถูกต้อง
เพราะ pointer ทุกชนิดมีขนาดเท่ากัน) จะทำให้ `-Wpedantic` เตือนเรื่อง **Undefined Behavior
ตามมาตรฐาน** ทันที

### ตารางสรุป Format Specifier ที่ใช้บ่อยที่สุด

| Specifier | ความหมาย |
|---|---|
| `%d`, `%i` | จำนวนเต็ม (`int`) ฐาน 10 มีเครื่องหมาย |
| `%u` | จำนวนเต็มฐาน 10 ไม่มีเครื่องหมาย (`unsigned int`) |
| `%x`, `%X` | จำนวนเต็มฐาน 16 (ตัวพิมพ์เล็ก/ใหญ่) |
| `%o` | จำนวนเต็มฐาน 8 |
| `%f` | จำนวนทศนิยม (`double`) แบบปกติ |
| `%e`, `%E` | จำนวนทศนิยมแบบ Scientific Notation (เช่น `1.234560e+02`) |
| `%g`, `%G` | เลือกอัตโนมัติระหว่าง `%f` กับ `%e` ตามความเหมาะสม |
| `%c` | อักขระเดี่ยว |
| `%s` | สตริง (null-terminated) |
| `%p` | ที่อยู่หน่วยความจำ (ต้อง cast เป็น `void *`) |
| `%%` | พิมพ์เครื่องหมาย `%` ตรงๆ |
| `%zu` | `size_t` (ผลลัพธ์ของ `sizeof`) |
| `%ld` / `%lu` | `long` / `unsigned long` |
| `%lld` / `%llu` | `long long` / `unsigned long long` |

## 3.3 ควบคุมรูปแบบการแสดงผล: Width, Precision และ Flags (Step 19)

โครงสร้างเต็มของ Format Specifier คือ:

```
%[flags][width][.precision]specifier
```

```c
/* printf_width_precision.c */
#include <stdio.h>

int main(void) {
    int   score = 7;
    double pi   = 3.14159265;

    printf("[%d]\n",   score);      /* [7]           ปกติ ไม่กำหนดความกว้าง */
    printf("[%5d]\n",  score);      /* [    7]        กว้าง 5 ช่อง ชิดขวา (default) */
    printf("[%-5d]\n", score);      /* [7    ]        กว้าง 5 ช่อง ชิดซ้าย (- flag) */
    printf("[%05d]\n", score);      /* [00007]        เติม 0 แทนช่องว่าง (0 flag) */
    printf("[%+d]\n",  score);      /* [+7]           แสดงเครื่องหมาย +/- เสมอ */
    printf("[% d]\n",  score);      /* [ 7]           เว้นช่องว่างแทนเครื่องหมายบวก */

    printf("[%.2f]\n",   pi);       /* [3.14]         precision ควบคุมทศนิยม 2 ตำแหน่ง */
    printf("[%10.2f]\n", pi);       /* [      3.14]   กว้าง 10 ช่อง ทศนิยม 2 ตำแหน่ง */
    printf("[%-10.2f]\n", pi);      /* [3.14      ]   กว้าง 10 ชิดซ้าย ทศนิยม 2 ตำแหน่ง */

    const char *word = "Hi";
    printf("[%10s]\n",  word);      /* [        Hi]   width สำหรับ string ก็ใช้ได้ */
    printf("[%-10s]\n", word);      /* [Hi        ] */
    printf("[%.1s]\n",  word);      /* [H]            precision ของ string = จำนวนอักขระสูงสุดที่แสดง */

    return 0;
}
```

| Flag/ส่วนประกอบ | ความหมาย |
|---|---|
| `-` | จัดชิดซ้าย (default คือชิดขวา) |
| `+` | แสดงเครื่องหมาย `+` หน้าเลขบวกเสมอ |
| `(space)` | เว้นช่องว่างหน้าเลขบวกแทนเครื่องหมาย |
| `0` | เติม `0` แทนช่องว่างด้านหน้า (ใช้กับตัวเลขเท่านั้น) |
| `width` (ตัวเลข) | ความกว้างขั้นต่ำของช่องแสดงผล |
| `.precision` | จำนวนทศนิยม (สำหรับ `%f`) หรือจำนวนอักขระสูงสุด (สำหรับ `%s`) |

Width และ Precision ยังกำหนดแบบ **Dynamic** ผ่าน `*` ได้ โดยส่งค่าจำนวนเต็มเข้าไปในตำแหน่ง
ก่อนตัวแปรจริง:

```c
/* dynamic_width.c */
#include <stdio.h>

int main(void) {
    int width = 8;
    int value = 42;

    printf("[%*d]\n", width, value);   /* เทียบเท่า [%8d] แต่กำหนด width จากตัวแปรได้ */

    return 0;
}
```

เทคนิคนี้มีประโยชน์มากเมื่อต้องจัดตารางข้อความให้ตรงคอลัมน์โดยความกว้างคำนวณมาจากข้อมูล
จริง (เช่น หาความยาวคำที่ยาวที่สุดในลิสต์ก่อน แล้วค่อยกำหนด width ตามนั้น)

## 3.4 scanf และปัญหา Newline ค้างใน Buffer (Step 20)

`scanf` อ่านข้อมูลจาก `stdin` ตาม Format String ที่กำหนด และ**ต้องส่ง Address ของตัวแปร**
(ใช้ `&`) เพื่อให้ `scanf` เขียนค่ากลับเข้าไปได้ (เราจะเข้าใจเหตุผลเชิงลึกเรื่อง Address
เมื่อเรียน Pointer ใน Part 8 — ตอนนี้ขอให้จำเป็นกฎไปก่อนว่า `scanf` ต้องการ `&` เสมอ ยกเว้น
ตัวแปรที่เป็น Array ของ `char` สำหรับ `%s`)

```c
/* scanf_basic.c */
#include <stdio.h>

int main(void) {
    int age;

    printf("กรุณาใส่อายุของคุณ: ");
    int result = scanf("%d", &age);

    if (result == 1) {
        printf("คุณอายุ %d ปี\n", age);
    } else {
        printf("รูปแบบข้อมูลไม่ถูกต้อง!\n");
    }

    return 0;
}
```

> **สำคัญมาก**: `scanf` คืนค่าเป็นจำนวนตัวแปรที่อ่านสำเร็จ **เสมอ ตรวจสอบค่านี้ทุกครั้ง**
> ถ้าผู้ใช้พิมพ์ตัวอักษรแทนตัวเลขตอนที่โปรแกรมคาดหวัง `%d`, `scanf` จะคืนค่า `0` (อ่านไม่
> สำเร็จเลย) และที่อันตรายกว่านั้นคือ**ตัวอักษรที่พิมพ์ผิดจะยังคงค้างอยู่ใน buffer** พร้อม
> ทำให้การเรียก `scanf` ครั้งถัดไปอ่านค่าผิดซ้ำอีก

### ปัญหาคลาสสิก: Newline ที่ค้างอยู่ใน stdin

```c
/* scanf_newline_problem.c */
#include <stdio.h>

int main(void) {
    char initial;
    int  age;

    printf("ใส่ตัวอักษรแรกของชื่อ: ");
    scanf("%c", &initial);          /* ผู้ใช้พิมพ์ "K" แล้วกด Enter */

    printf("ใส่อายุ: ");
    scanf("%d", &age);              /* คาดหวังให้ถามใหม่ แต่กลับข้ามไปเฉยๆ! */

    printf("ชื่อขึ้นต้นด้วย '%c' อายุ %d ปี\n", initial, age);

    return 0;
}
```

ถ้าผู้ใช้พิมพ์ `K` แล้วกด Enter ปัญหาคือ `%c` อ่านเฉพาะตัวอักษร `K` เท่านั้น **Newline
(`\n`) ที่เกิดจากการกด Enter จะยังค้างอยู่ใน stdin buffer** พอถึง `scanf("%d", &age)`
มันจะพยายามอ่านตัวเลข แต่ยังพบ Newline ค้างอยู่ ในกรณีของ `%d` มันจะข้าม whitespace
(รวม Newline) ไปเองโดยอัตโนมัติแล้วรอผู้ใช้พิมพ์ตัวเลขจริง — แต่ถ้าลองสลับโค้ดให้ `%c`
มาเป็นตัวที่สอง ปัญหาจะยิ่งชัดเจนกว่าเดิม:

```c
/* scanf_newline_problem2.c */
#include <stdio.h>

int main(void) {
    int  age;
    char initial;

    printf("ใส่อายุ: ");
    scanf("%d", &age);              /* ผู้ใช้พิมพ์ "25" แล้วกด Enter */

    printf("ใส่ตัวอักษรแรกของชื่อ: ");
    scanf(" %c", &initial);         /* สังเกตช่องว่างก่อน %c! นี่คือทางแก้ */

    printf("อายุ %d ปี ชื่อขึ้นต้นด้วย '%c'\n", age, initial);

    return 0;
}
```

**ทางแก้คือใส่ช่องว่าง (space) ไว้ก่อน `%c` ในรูปแบบ `" %c"`** ช่องว่างใน Format String
ของ `scanf` มีความหมายพิเศษ: มันสั่งให้ `scanf` **ข้าม whitespace ทุกชนิดที่ค้างอยู่**
(รวมถึง Newline จากการกด Enter ครั้งก่อน) ก่อนเริ่มอ่านค่าจริง ในขณะที่ `%d`, `%f`, `%s`
มีพฤติกรรมนี้อยู่แล้วโดยอัตโนมัติ (ข้าม leading whitespace เสมอ) มีเพียง `%c` เท่านั้นที่
**อ่านทุกตัวอักษรตรงๆ รวมถึง Newline ด้วย** จึงต้องเติมช่องว่างกำกับเองเมื่อใช้ `%c`

## 3.5 stdin, stdout, stderr และ fflush (Step 21)

ทุกโปรแกรม C ที่รันบนระบบที่มี Operating System จะได้รับ 3 Stream มาตรฐานโดยอัตโนมัติ
ตั้งแต่เริ่มโปรแกรม:

| Stream | ความหมาย | ค่า Default | Buffering |
|---|---|---|---|
| `stdin` | Standard Input — แหล่งข้อมูลเข้า | คีย์บอร์ด | Line-buffered (เมื่อเชื่อมกับ terminal) |
| `stdout` | Standard Output — ผลลัพธ์ปกติของโปรแกรม | หน้าจอ terminal | Line-buffered (terminal) / Fully-buffered (redirect ไปไฟล์) |
| `stderr` | Standard Error — ข้อความ error/แจ้งเตือน | หน้าจอ terminal | **Unbuffered เสมอ** |

```c
/* three_streams.c */
#include <stdio.h>

int main(void) {
    fprintf(stdout, "นี่คือข้อความปกติ (stdout)\n");
    fprintf(stderr, "นี่คือข้อความ error (stderr)\n");
    printf("printf() คือ fprintf(stdout, ...) แบบย่อ\n");

    return 0;
}
```

### ทำไมต้องแยก stdout กับ stderr?

เหตุผลสำคัญที่สุดคือ**การ Redirect** — ผู้ใช้สามารถแยกทางไปของผลลัพธ์ปกติกับข้อความ error
ได้อย่างอิสระผ่าน Shell:

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 three_streams.c -o three_streams

./three_streams                       # เห็นทั้งสองข้อความบนหน้าจอ
./three_streams > output.txt          # stdout ไปไฟล์ output.txt, stderr ยังขึ้นจอ
./three_streams 2> errors.txt         # stderr ไปไฟล์ errors.txt, stdout ยังขึ้นจอ
./three_streams > out.txt 2> err.txt  # แยกไปคนละไฟล์
./three_streams > all.txt 2>&1        # รวมทั้งสอง stream ไปไฟล์เดียวกัน
```

นี่คือเหตุผลที่ **ข้อความ Error ควรพิมพ์ผ่าน `stderr` เสมอ ไม่ใช่ `stdout`** — เพื่อให้ผู้ใช้
หรือระบบ Script ที่ต่อยอด (เช่น CI/CD Pipeline) สามารถกรอง log ปกติออกจากข้อความ error
ได้อย่างสะดวก โดยไม่ต้องแก้โค้ดโปรแกรม

### fflush: บังคับล้าง Output Buffer

`stdout` เมื่อเชื่อมกับไฟล์หรือ pipe (ไม่ใช่ terminal) จะเป็นแบบ **Fully Buffered** คือ
ข้อความจะถูกเก็บไว้ใน buffer ก่อน แล้วค่อยเขียนออกจริงเมื่อ buffer เต็มหรือโปรแกรมจบ
ทำให้บางครั้งข้อความที่ `printf` ไปแล้วยังไม่ปรากฏขึ้นจริงในทันที:

```c
/* fflush_demo.c */
#include <stdio.h>
#include <unistd.h>   /* สำหรับ sleep() */

int main(void) {
    printf("กำลังประมวลผล");
    fflush(stdout);      /* บังคับให้ข้อความข้างบนแสดงผลทันที ก่อนเข้า loop รอ */

    for (int i = 0; i < 3; i++) {
        sleep(1);
        printf(".");
        fflush(stdout);  /* ถ้าไม่ fflush ผู้ใช้อาจไม่เห็นจุดแสดงทีละตัว */
    }

    printf(" เสร็จแล้ว!\n");
    return 0;
}
```

กรณีใช้งาน `fflush(stdout)` ที่พบบ่อยที่สุดคือ **ก่อนเรียก `scanf`** เมื่อ `printf` ก่อน
หน้าไม่มี Newline ท้ายข้อความ (เพราะต้องการให้ prompt กับ input อยู่บรรทัดเดียวกัน) —
ในทางปฏิบัติเมื่อ `stdout` เชื่อมกับ terminal (Line-buffered) ข้อความมักจะแสดงผลทันทีที่
เรียก `scanf` อยู่แล้วเพราะ `scanf` จะ flush stream ที่เกี่ยวข้องให้เป็นธรรมเนียมปฏิบัติทั่วไป
ของ libc แต่การเรียก `fflush(stdout)` เองอย่างชัดเจนคือแนวทางที่ปลอดภัยและแน่นอนที่สุด
ในทุกสถานการณ์ (รวมถึงตอน redirect output)

> **ข้อควรระวัง**: `fflush(stdin)` เป็น **Undefined Behavior ตามมาตรฐาน C** (แม้บาง
> Compiler เช่น MSVC บน Windows จะรองรับให้ล้าง input buffer ได้ก็ตาม) มาตรฐานนิยาม
> `fflush` ไว้สำหรับ **Output Stream เท่านั้น** ห้ามใช้ `fflush(stdin)` เพื่อล้าง input
> buffer เด็ดขาดถ้าต้องการโค้ดที่พกพาได้ — วิธีล้าง input buffer ที่ถูกต้องจะพูดถึงใน 3.8

## 3.6 getchar และ putchar: อ่าน-เขียนทีละตัวอักษร (Step 22)

`getchar()` อ่านตัวอักษรถัดไปจาก `stdin` ทีละตัว คืนค่าเป็น `int` (ไม่ใช่ `char`!) ส่วน
`putchar()` เขียนตัวอักษรหนึ่งตัวออก `stdout`

```c
/* getchar_putchar_basic.c */
#include <stdio.h>

int main(void) {
    printf("พิมพ์ตัวอักษรอะไรก็ได้แล้วกด Enter: ");

    int c = getchar();   /* ต้องเก็บใน int ไม่ใช่ char! */
    printf("คุณพิมพ์: ");
    putchar(c);
    putchar('\n');

    return 0;
}
```

> **ทำไม `getchar()` ต้องคืนค่าเป็น `int` ไม่ใช่ `char`?** เพราะ `getchar()` ต้องสามารถ
> คืนค่าพิเศษ **`EOF`** (End Of File, โดยทั่วไปมีค่า `-1`) เพื่อบอกว่า "อ่านจนหมด stream
> แล้ว ไม่มีอะไรให้อ่านอีก" ถ้าเก็บผลลัพธ์ไว้ใน `char` ซึ่งบนบางระบบเป็น `unsigned char`
> (มีค่า 0-255 เท่านั้น ไม่มีทางเป็น -1 ได้) จะทำให้แยกแยะ `EOF` ออกจากตัวอักษรจริงไม่ได้
> **นี่คือกฎที่ต้องจำขึ้นใจ: ค่าที่ได้จาก `getchar()` ต้องเก็บในตัวแปรชนิด `int` เสมอ**

### ตัวอย่างจริง: อ่านทีละตัวอักษรจนจบ Input พร้อมนับจำนวน

```c
/* count_characters.c */
#include <stdio.h>

int main(void) {
    int c;
    long total_chars = 0;
    long total_lines = 0;

    printf("พิมพ์ข้อความหลายบรรทัด แล้วกด Ctrl+D (Linux/macOS) เพื่อจบ:\n");

    while ((c = getchar()) != EOF) {
        total_chars++;
        if (c == '\n') {
            total_lines++;
        }
    }

    printf("\nจำนวนตัวอักษรทั้งหมด: %ld\n", total_chars);
    printf("จำนวนบรรทัดทั้งหมด : %ld\n", total_lines);

    return 0;
}
```

ทดสอบโดยการ Redirect ไฟล์เข้าไปแทนการพิมพ์เอง:

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 count_characters.c -o count_characters
printf "Hello\nWorld\n" | ./count_characters
```

ผลลัพธ์:

```
จำนวนตัวอักษรทั้งหมด: 12
จำนวนบรรทัดทั้งหมด : 2
```

รูปแบบ `while ((c = getchar()) != EOF)` เป็น **Idiom (สำนวนโค้ด)** ที่พบบ่อยที่สุดรูปแบบ
หนึ่งในภาษา C สำหรับอ่านข้อมูลทีละตัวจนจบ stream ควรจดจำรูปแบบนี้ให้ขึ้นใจ เพราะจะพบซ้ำ
อีกหลายครั้งตลอดหลักสูตร โดยเฉพาะเมื่อเรียนเรื่อง File I/O ใน Part 13

## 3.7 fgets เทียบกับ scanf("%s") สำหรับการรับ String (Step 23)

`scanf("%s", buffer)` มีปัญหาใหญ่ 2 ข้อ: (1) **หยุดอ่านที่ whitespace ตัวแรก** ทำให้รับ
ข้อความที่มีช่องว่างไม่ได้ (เช่น ชื่อ-นามสกุล) และ (2) **ไม่มีการจำกัดความยาวถ้าไม่ระบุ
width เอง** ทำให้เสี่ยงต่อ Buffer Overflow อย่างร้ายแรง (จะพูดถึงเจาะลึกใน 3.8)

`fgets` เป็นทางเลือกที่ปลอดภัยกว่ามาก เพราะ**บังคับให้ระบุขนาด buffer สูงสุดเสมอ** และ
อ่านได้ทั้งบรรทัด (รวมช่องว่าง) จนกว่าจะเจอ Newline หรือ buffer เต็ม

```c
/* fgets_vs_scanf.c */
#include <stdio.h>
#include <string.h>

int main(void) {
    char buffer1[20];
    char buffer2[50];

    printf("ทดสอบ scanf(\"%%s\") - ลองพิมพ์ \"John Smith\": ");
    scanf("%19s", buffer1);           /* หยุดที่ช่องว่าง จะได้แค่ "John" */
    printf("scanf ได้ผลลัพธ์: \"%s\"\n\n", buffer1);

    /* ล้าง newline ที่ค้างจาก scanf ก่อนเรียก fgets */
    int c;
    while ((c = getchar()) != '\n' && c != EOF) { }

    printf("ทดสอบ fgets() - ลองพิมพ์ \"John Smith\": ");
    fgets(buffer2, sizeof(buffer2), stdin);   /* อ่านทั้งบรรทัด รวมช่องว่าง */

    /* fgets เก็บ '\n' ท้ายบรรทัดไว้ด้วย ต้องตัดออกเอง */
    size_t len = strlen(buffer2);
    if (len > 0 && buffer2[len - 1] == '\n') {
        buffer2[len - 1] = '\0';
    }
    printf("fgets ได้ผลลัพธ์: \"%s\"\n", buffer2);

    return 0;
}
```

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 fgets_vs_scanf.c -o fgets_vs_scanf
```

ทดสอบด้วย input ที่เตรียมไว้ล่วงหน้า:

```bash
printf "John Smith\nJohn Smith\n" | ./fgets_vs_scanf
```

ผลลัพธ์:

```
ทดสอบ scanf("%s") - ลองพิมพ์ "John Smith": scanf ได้ผลลัพธ์: "John"

ทดสอบ fgets() - ลองพิมพ์ "John Smith": fgets ได้ผลลัพธ์: "John Smith"
```

### ตารางเปรียบเทียบ scanf("%s") กับ fgets

| ประเด็น | `scanf("%s", buf)` | `fgets(buf, size, stdin)` |
|---|---|---|
| หยุดอ่านที่ | Whitespace ตัวแรก (space, tab, newline) | Newline หรือครบขนาด buffer |
| รับข้อความที่มีช่องว่างได้ไหม | ไม่ได้ | ได้ |
| ป้องกัน Buffer Overflow เองไหม | **ไม่ป้องกัน** ถ้าไม่ระบุ width (`%19s`) | ป้องกันเสมอ เพราะบังคับส่งขนาด buffer |
| เก็บ Newline ท้ายสตริงไหม | ไม่เก็บ | เก็บไว้ (ต้องตัดเองถ้าไม่ต้องการ) |
| ความปลอดภัยโดยรวม | ต่ำ ถ้าใช้ไม่ระวัง | สูงกว่ามาก แนะนำให้ใช้เป็นค่า default |

## 3.8 ข้อควรระวังเรื่อง Buffer Overflow กับ scanf และแนวทางที่ปลอดภัย (Step 24)

### อันตรายของ scanf("%s") แบบไม่จำกัดความยาว

```c
/* DANGEROUS - อย่านำไปใช้จริง แสดงเพื่อการศึกษาเท่านั้น */
char name[10];
scanf("%s", name);   /* ถ้าผู้ใช้พิมพ์เกิน 9 ตัวอักษร -> เขียนทับหน่วยความจำนอก buffer! */
```

โค้ดข้างบนคือช่องโหว่ความปลอดภัยคลาสสิกที่เรียกว่า **Buffer Overflow** — ถ้าผู้ใช้ (หรือ
ผู้ไม่หวังดี) ป้อนข้อความยาวกว่าขนาด `name` array `scanf` จะยังคงเขียนข้อมูลต่อไปเรื่อยๆ
โดยไม่ตรวจสอบขอบเขต ทำให้เขียนทับหน่วยความจำส่วนอื่นที่อยู่ติดกัน ซึ่งอาจนำไปสู่โปรแกรม
Crash หรือแย่กว่านั้นคือถูกโจมตีแบบ **Stack Buffer Overflow Exploit** (การโจมตีความปลอดภัย
รูปแบบนี้เคยสร้างความเสียหายรุนแรงในประวัติศาสตร์ซอฟต์แวร์มาแล้วนับไม่ถ้วน) เราจะเจาะลึก
เรื่อง Memory Safety และการโจมตีลักษณะนี้อีกครั้งใน Module ที่เกี่ยวกับ Security (Part 115)

**ฟังก์ชัน `gets()` ที่เคยมีในมาตรฐาน C89/C99 มีปัญหานี้อย่างรุนแรงจนถูก _ถอดออกจาก
มาตรฐาน C11 ไปเลย_** ห้ามใช้ `gets()` เด็ดขาดในโค้ดใดๆ (ถ้า compiler ยังรองรับอยู่จะเป็น
เพราะ extension ของ library เท่านั้น ไม่ใช่มาตรฐาน)

### แนวทางที่ปลอดภัย

**1. ระบุ Width จำกัดเสมอเมื่อใช้ `%s` กับ scanf**

```c
char name[20];
scanf("%19s", name);   /* จำกัดไม่เกิน 19 ตัวอักษร + 1 ตัวสำหรับ '\0' = พอดี 20 byte */
```

สังเกตว่าตัวเลข width ต้อง**น้อยกว่าขนาด buffer จริง 1 ตัวเสมอ** เพราะ `scanf` จะเติม
`'\0'` (null terminator) ต่อท้ายให้อัตโนมัติ ถ้า buffer มีขนาด 20 byte ต้องระบุ `%19s`
ไม่ใช่ `%20s`

**2. ใช้ `fgets` แทน `scanf("%s")` เป็นค่า default เสมอเมื่อรับข้อความ**

ดังที่แสดงในหัวข้อ 3.7 — `fgets` ปลอดภัยกว่าเพราะบังคับระบุขนาด buffer ผ่านพารามิเตอร์
โดยตรง ไม่มีทางลืมได้

**3. ตรวจสอบ Return Value ของ scanf เสมอ**

```c
int result = scanf("%d", &age);
if (result != 1) {
    printf("ข้อมูลไม่ถูกต้อง!\n");
    /* จัดการ error ต่อไป */
}
```

**4. ล้าง Input Buffer เมื่อข้อมูลไม่ถูกต้อง**

เมื่อ `scanf("%d", ...)` อ่านล้มเหลว (เช่น ผู้ใช้พิมพ์ตัวอักษรแทนตัวเลข) ตัวอักษรที่พิมพ์ผิด
จะยังค้างอยู่ใน stdin buffer ทำให้การอ่านครั้งถัดไปผิดพลาดซ้ำ ฟังก์ชันช่วยมาตรฐานที่ใช้กัน
แพร่หลายคือ:

```c
/* clear_input_buffer.c */
#include <stdio.h>

void clear_input_buffer(void) {
    int c;
    while ((c = getchar()) != '\n' && c != EOF) {
        /* อ่านทิ้งไปเรื่อยๆ จนกว่าจะเจอ newline หรือจบไฟล์ */
    }
}

int main(void) {
    int age;

    printf("ใส่อายุ (ตัวเลขเท่านั้น): ");
    while (scanf("%d", &age) != 1) {
        printf("ข้อมูลไม่ถูกต้อง กรุณาใส่ตัวเลขเท่านั้น: ");
        clear_input_buffer();
    }

    printf("อายุที่รับได้: %d ปี\n", age);
    return 0;
}
```

ฟังก์ชัน `clear_input_buffer` นี้จะกลายเป็นเครื่องมือที่ใช้ซ้ำแทบทุกครั้งที่โปรแกรมต้อง
รับ input จากผู้ใช้แบบโต้ตอบตลอดทั้งหลักสูตร ควรจดจำรูปแบบนี้ให้ขึ้นใจ

## ข้อผิดพลาดที่พบบ่อย (Common Pitfalls)

1. **Format Specifier ไม่ตรงชนิดตัวแปร** — เช่น ใช้ `%d` กับตัวแปร `double` หรือ `%f` กับ
   `int` เป็นสาเหตุของ Undefined Behavior ที่พบบ่อยที่สุดอย่างหนึ่งในภาษา C แม้โปรแกรมอาจ
   "ดูเหมือนทำงานได้" บนเครื่องหนึ่ง แต่พังบนอีกเครื่อง `-Wall -Wextra` จะจับ error ประเภทนี้
   ได้เกือบทั้งหมด (`-Wformat`) — **ห้ามปิด Warning นี้เด็ดขาด**

2. **ลืม `&` หน้าตัวแปรใน scanf** — `scanf("%d", age);` (ไม่มี `&`) เป็นข้อผิดพลาดที่พบบ่อย
   ที่สุดของมือใหม่ ทำให้ `scanf` พยายามเขียนข้อมูลไปยัง Address ที่ผิด (ค่าของ `age`
   ถูกตีความเป็น Address) เกิด Undefined Behavior หรือโปรแกรม Crash ทันที `-Wall` จะเตือน
   ด้วย `-Wformat` ว่า "expects argument of type 'int *', but argument has type 'int'"

3. **Newline ค้างใน stdin หลังใช้ `%c` หรือ `%d`/`%f` ตามด้วย `fgets`** — ดังที่อธิบายใน 3.4
   และ 3.7 การผสม `scanf` กับ `fgets` โดยไม่ล้าง buffer ก่อนเป็นสาเหตุของบั๊กที่มือใหม่
   งงที่สุด (โปรแกรม "ข้าม" การถามคำถามไปเฉยๆ)

4. **ใช้ `scanf("%s", buf)` โดยไม่จำกัด width** — เสี่ยง Buffer Overflow เต็มรูปแบบ ดังที่
   อธิบายในหัวข้อ 3.8 ควรระบุ width ทุกครั้ง (`%19s` สำหรับ buffer ขนาด 20) หรือเปลี่ยนไปใช้
   `fgets` แทน

5. **เก็บผลลัพธ์ของ `getchar()` ไว้ในตัวแปรชนิด `char`** — ทำให้ตรวจจับ `EOF` ไม่ได้อย่าง
   ถูกต้อง (โดยเฉพาะถ้า `char` เป็น `unsigned` บนแพลตฟอร์มนั้น) ต้องเก็บใน `int` เสมอ

6. **ไม่ตรวจสอบ Return Value ของ scanf** — การไม่ตรวจสอบว่า `scanf` อ่านสำเร็จกี่ค่า ทำให้
   โปรแกรมใช้ค่าขยะ (Garbage Value) ที่ไม่เคยถูกกำหนดจริงต่อไปโดยไม่รู้ตัว ควรตรวจสอบ
   Return Value เสมอในโค้ดที่ต้องรับ input จากผู้ใช้จริง

## แบบฝึกหัดท้ายบท

1. เขียนโปรแกรมที่ประกาศตัวแปร `int` หนึ่งตัว แล้วใช้ `printf` แสดงค่าของมันในรูปแบบ
   ทศนิยม, เลขฐาน 16, เลขฐาน 8 พร้อมกันในบรรทัดเดียว (ใช้ค่า `255`)

2. เขียนโปรแกรมที่ใช้ `printf` จัดตารางแสดงชื่อสินค้า 3 รายการและราคา โดยให้ชื่อสินค้าชิด
   ซ้ายกว้าง 15 ช่อง และราคาชิดขวากว้าง 10 ช่อง ทศนิยม 2 ตำแหน่ง (ใช้ width/flags ที่เรียน
   ในหัวข้อ 3.3)

3. เขียนโปรแกรมที่สาธิตปัญหา Newline ค้างจากหัวข้อ 3.4 (รับ `%c` ตามด้วย `%d`) แล้วแก้ไข
   ให้ถูกต้องด้วยการเติมช่องว่างหน้า `%c`

4. เขียนโปรแกรมที่รับชื่อ-นามสกุลแบบเต็ม (มีช่องว่างได้) ด้วย `fgets` แล้วตัด Newline ท้าย
   ออก จากนั้นแสดงข้อความทักทายด้วยชื่อที่รับมา

5. เขียนฟังก์ชัน `clear_input_buffer()` (ตามหัวข้อ 3.8) แล้วเขียนโปรแกรมที่วนถามผู้ใช้
   ใส่ตัวเลขจนกว่าจะใส่ถูกต้อง โดยแสดงข้อความแจ้งเตือนทุกครั้งที่ใส่ผิด

6. เขียนโปรแกรมที่ใช้ `getchar()`/`putchar()` อ่านข้อความจาก `stdin` ทีละตัวอักษรจนจบ
   (`EOF`) แล้วแปลงตัวอักษรภาษาอังกฤษตัวพิมพ์เล็กทั้งหมดให้เป็นตัวพิมพ์ใหญ่ก่อนพิมพ์ออกไป
   (คำใบ้: ตัวอักษร `'a'` ถึง `'z'` ลบด้วย 32 จะได้ตัวพิมพ์ใหญ่ที่ตรงกัน)

### แนวทางเฉลยข้อ 2

```c
/* product_table.c */
#include <stdio.h>

int main(void) {
    printf("%-15s%10s\n", "สินค้า", "ราคา");
    printf("%-15s%10.2f\n", "ปากกา", 15.0);
    printf("%-15s%10.2f\n", "สมุด", 25.5);
    printf("%-15s%10.2f\n", "ยางลบ", 8.75);

    return 0;
}
```

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 product_table.c -o product_table
./product_table
```

ผลลัพธ์จริงที่ได้ (คัดลอกตรงจาก terminal):

```
สินค้าราคา
ปากกา     15.00
สมุด        25.50
ยางลบ      8.75
```

สังเกตว่าคอลัมน์**ไม่ได้เรียงตรงกันสวยงามอย่างที่คาดหวัง** ทั้งที่ใช้ `%-15s` และ `%10s`
เหมือนกันทุกบรรทัด! สาเหตุคือ `printf` คำนวณ width จาก**จำนวน byte** ของสตริง ไม่ใช่
"จำนวนตัวอักษรที่มองเห็น" — อักขระภาษาไทยแต่ละตัวเข้ารหัสแบบ UTF-8 ใช้ 3 byte ต่อ 1
ตัวอักษรที่มองเห็น ในขณะที่อักขระภาษาอังกฤษ 1 ตัวใช้เพียง 1 byte ดังนั้นคำว่า `"สินค้า"`
ซึ่งมองเห็น 6 ตัวอักษร แต่กินพื้นที่ไปแล้ว 18 byte เกินกว่า width ที่กำหนด (15) ไปมาก ทำให้
`%-15s` ไม่เติมช่องว่างเพิ่มให้เลย (เพราะเนื้อหายาวกว่า width ที่ระบุอยู่แล้ว)

> **ข้อควรจำ**: `printf` เหมาะกับการจัดคอลัมน์ที่เป็นภาษาอังกฤษ/ตัวเลขล้วนเท่านั้น (เช่น
> คอลัมน์ราคาในตัวอย่างนี้ที่จัดชิดขวาได้ตรงเป๊ะ) เมื่อต้องจัดตารางข้อความหลายภาษาที่มี
> อักขระ Multi-byte ปนอยู่ (เช่นภาษาไทย, ญี่ปุ่น, จีน) อย่างแม่นยำในงานจริง จำเป็นต้องใช้
> Library เฉพาะทางที่คำนวณความกว้างการแสดงผล (Display Width) แยกจากจำนวน byte
> ตัวอย่างนี้จงใจแสดงผลลัพธ์ที่ไม่สวยงามไว้ เพื่อให้เห็นข้อจำกัดนี้ชัดเจนตั้งแต่ต้น

### แนวทางเฉลยข้อ 5

```c
/* validated_input.c */
#include <stdio.h>

void clear_input_buffer(void) {
    int c;
    while ((c = getchar()) != '\n' && c != EOF) {
        /* discard */
    }
}

int main(void) {
    int number;

    printf("กรุณาใส่ตัวเลขจำนวนเต็ม: ");
    while (scanf("%d", &number) != 1) {
        printf("ข้อมูลไม่ใช่ตัวเลข! กรุณาลองใหม่: ");
        clear_input_buffer();
    }
    clear_input_buffer();   /* ล้าง newline ที่เหลือจากการอ่านครั้งที่สำเร็จด้วย */

    printf("คุณใส่เลข: %d\n", number);
    return 0;
}
```

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 validated_input.c -o validated_input
printf "abc\nxyz\n42\n" | ./validated_input
```

ผลลัพธ์:

```
กรุณาใส่ตัวเลขจำนวนเต็ม: ข้อมูลไม่ใช่ตัวเลข! กรุณาลองใหม่: ข้อมูลไม่ใช่ตัวเลข! กรุณาลองใหม่: คุณใส่เลข: 42
```

จุดสำคัญของข้อนี้คือการเรียก `clear_input_buffer()` **สองจุดที่ต่างจุดประสงค์กัน**: ครั้งแรก
ภายใน loop เพื่อล้างข้อมูลผิดที่พิมพ์เข้ามา (`"abc"`, `"xyz"`) และครั้งที่สองหลัง loop จบ
เพื่อล้าง Newline ที่ยังค้างอยู่หลังจากอ่านตัวเลข `42` สำเร็จ (เพราะ `%d` ไม่กิน Newline
ท้ายไปด้วย) — ถ้าโปรแกรมมีการอ่านข้อมูลชนิดอื่นต่อจากนี้อีก (เช่น `fgets`) การล้าง Newline
ค้างจุดนี้จำเป็นมาก ไม่เช่นนั้นจะเจอปัญหาเดียวกับหัวข้อ 3.4 อีก

## สรุปท้ายบท

ใน Part นี้เราได้:

- เจาะลึก Format Specifier ของ `printf` ครบทุกรูปแบบที่ใช้งานจริง ตั้งแต่จำนวนเต็ม ทศนิยม
  เลขฐาน ไปจนถึง Pointer และรู้จักการควบคุม Width, Precision และ Flags
- เข้าใจกลไกของ `scanf` และปัญหา Newline ค้างใน Buffer ซึ่งเป็นบั๊กคลาสสิกที่มือใหม่ทุกคน
  ต้องเจอ พร้อมรู้วิธีแก้ด้วยช่องว่างนำหน้า `%c`
- แยกแยะความแตกต่างของ `stdin`, `stdout`, `stderr` และรู้วิธีใช้ `fflush` อย่างถูกต้อง
- ใช้ `getchar`/`putchar` อ่าน-เขียนข้อมูลทีละตัวอักษร และเข้าใจว่าทำไมต้องเก็บผลลัพธ์ใน
  `int`
- เข้าใจข้อจำกัดของ `scanf("%s")` เทียบกับความปลอดภัยของ `fgets` และรู้จักอันตรายของ
  Buffer Overflow พร้อมแนวทางป้องกันที่ใช้ได้จริง
