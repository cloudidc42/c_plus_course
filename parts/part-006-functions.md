## 6.1 ทำไมต้องมีฟังก์ชัน และ Prototype vs Definition (Step 41)

ถ้าลองสังเกตโค้ดใน Part 1-5 ที่ผ่านมา ทุกอย่างถูกยัดไว้ใน `main()` ฟังก์ชันเดียวทั้งหมด
เมื่อโปรแกรมมีขนาดใหญ่ขึ้น การเขียนแบบนี้จะเกิดปัญหา 3 อย่าง:

1. **โค้ดซ้ำซ้อน** — ถ้าต้องคำนวณสิ่งเดียวกันหลายจุด ต้อง copy-paste โค้ดซ้ำไปเรื่อยๆ
2. **อ่านยาก** — `main()` ที่มีหลายร้อยบรรทัดทำให้มองภาพรวมของโปรแกรมไม่ออก
3. **แก้บั๊กยาก** — ถ้าโค้ดซ้ำอยู่ 5 จุด แล้วพบบั๊ก ต้องไปแก้ทั้ง 5 จุดให้ครบ (และมักลืมแก้บางจุด)

**ฟังก์ชัน (Function)** คือการห่อกลุ่มคำสั่งที่ทำงานอย่างใดอย่างหนึ่งไว้ด้วยกัน ตั้งชื่อให้มัน
แล้วเรียกใช้ซ้ำได้จากทุกที่ในโปรแกรม เปรียบเหมือนการสร้าง "เครื่องจักรย่อย" ที่รับวัตถุดิบ
(พารามิเตอร์) เข้าไป แล้วส่งผลผลิต (ค่าที่คืนกลับ) ออกมา โดยไม่ต้องรู้ว่าข้างในเครื่องจักร
ทำงานอย่างไรก็ใช้งานได้

### โครงสร้างของฟังก์ชันในภาษา C

```c
ชนิดข้อมูลที่คืนค่า ชื่อฟังก์ชัน(พารามิเตอร์) {
    // เนื้อหาการทำงาน
    return ค่าที่จะคืนกลับ;   // ถ้าชนิดคืนค่าเป็น void จะไม่มีบรรทัดนี้ก็ได้
}
```

ตัวอย่างฟังก์ชันบวกเลข 2 จำนวน:

```c
/*
 * add_demo.c
 * ตัวอย่างฟังก์ชันแรก: บวกเลข 2 จำนวน
 */
#include <stdio.h>

/* ---------- Function Prototype ---------- */
int add(int a, int b);

int main(void) {
    int result = add(3, 5);
    printf("3 + 5 = %d\n", result);

    printf("7 + 2 = %d\n", add(7, 2));   // เรียกใช้ฟังก์ชันซ้ำได้ไม่จำกัด

    return 0;
}

/* ---------- Function Definition ---------- */
int add(int a, int b) {
    return a + b;
}
```

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 add_demo.c -o add_demo
./add_demo
```

```
3 + 5 = 8
7 + 2 = 9
```

### Prototype vs Definition ต่างกันอย่างไร

| | Function Prototype | Function Definition |
|---|---|---|
| หน้าที่ | บอก compiler ว่าฟังก์ชันนี้มีอยู่ ชื่ออะไร รับ-คืนค่าอะไร | เนื้อหาจริงที่ฟังก์ชันทำงาน |
| รูปแบบ | `int add(int a, int b);` (จบด้วย `;` ไม่มี body) | `int add(int a, int b) { ... }` (มี body) |
| ตำแหน่งที่วาง | ก่อน `main()` (หรือในไฟล์ `.h`) | หลัง `main()` ได้ หรือก่อนก็ได้ |
| จำเป็นเสมอไหม | จำเป็นถ้า definition อยู่ **หลัง** จุดที่เรียกใช้ | จำเป็นเสมอ (ต้องมีอย่างน้อย 1 ที่ในโปรแกรม) |

**ทำไมต้องมี Prototype ทั้งที่มี Definition อยู่แล้ว?** เพราะ Compiler อ่านไฟล์ **จากบนลงล่าง
เพียงรอบเดียว** ถ้าเรียกใช้ `add(3, 5)` ใน `main()` ก่อนที่ compiler จะเห็น definition ของ `add`
เลย (เพราะ definition วางไว้ท้ายไฟล์) compiler จะไม่รู้จักฟังก์ชันนี้ Prototype จึงทำหน้าที่เป็น
"การประกาศล่วงหน้า" บอก compiler ว่า "เดี๋ยวจะมีฟังก์ชันนี้ปรากฏทีหลังนะ ตอนนี้เชื่อไปก่อนว่ามี"

ลองไม่ใส่ prototype ดูว่าเกิดอะไรขึ้น:

```c
#include <stdio.h>

int main(void) {
    int result = add(3, 5);   // เรียกใช้ก่อนที่ compiler จะรู้จัก add
    printf("%d\n", result);
    return 0;
}

int add(int a, int b) {       // definition อยู่หลัง main() โดยไม่มี prototype นำหน้า
    return a + b;
}
```

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 no_prototype.c -o no_prototype
```

จะได้ **Warning ที่รุนแรงมาก** ทันที:

```
warning: implicit declaration of function 'add' [-Wimplicit-function-declaration]
```

แม้โปรแกรมนี้จะยังคอมไพล์ผ่านและรันได้ (เพราะมาตรฐาน C99/C17 ยังคงให้เป็นแค่ Warning ไม่ใช่
Error โดย default) แต่ **ห้ามมองข้าม Warning นี้เด็ดขาด** เพราะในกรณีทั่วไปที่ชนิดคืนค่าและ
พารามิเตอร์ของฟังก์ชันไม่ตรงกับที่ compiler เดาไว้ (ค่า default ที่ compiler สมัยก่อนใช้คือ
`int` เสมอ) จะทำให้เกิด Undefined Behavior ที่ตรวจจับได้ยากมาก และ compiler บางตัว/บาง
มาตรฐาน (เช่น C23 ขึ้นไป หรือเมื่อเปิด `-Werror`) จะเปลี่ยน Warning นี้ให้กลายเป็น **Error
ที่คอมไพล์ไม่ผ่านทันที** มาตรฐาน C สมัยใหม่จึงกำหนดให้ต้องมี Prototype หรือ Definition
ปรากฏก่อนจุดที่เรียกใช้เสมอ ต่างจาก C89 เก่าที่ยอมให้ "เดา" ชนิดข้อมูลแบบ implicit ได้
(ซึ่งอันตรายมาก และเป็นสาเหตุของบั๊กมากมายในโค้ดยุคเก่า) **แนวทางที่ถูกต้องเสมอคือใส่
Prototype ของทุกฟังก์ชันไว้ก่อน `main()`**

## 6.2 Parameter และ Pass by Value (Step 42)

**Pass by Value** คือกลไกการส่งพารามิเตอร์แบบเดียวที่ภาษา C มีให้ใช้งานโดยตรง หลักการคือ
**เมื่อเรียกฟังก์ชัน ค่าของ argument จะถูก "copy" ใส่เข้าไปในพารามิเตอร์ของฟังก์ชัน** ฟังก์ชัน
ทำงานกับ "สำเนา" นี้เท่านั้น ไม่ได้แตะต้องตัวแปรต้นฉบับเลยแม้แต่น้อย

```c
/*
 * pass_by_value_demo.c
 * พิสูจน์ว่า C ส่งพารามิเตอร์แบบ Pass by Value เท่านั้น
 */
#include <stdio.h>

void try_to_double(int x);

int main(void) {
    int number = 10;

    printf("ก่อนเรียกฟังก์ชัน: number = %d\n", number);
    try_to_double(number);
    printf("หลังเรียกฟังก์ชัน:  number = %d\n", number);   // ยังคงเป็น 10 เหมือนเดิม!

    return 0;
}

void try_to_double(int x) {
    x = x * 2;                 // แก้ไขแค่ "สำเนา" ของ x เท่านั้น
    printf("ในฟังก์ชัน:      x = %d\n", x);
}
```

ผลลัพธ์:

```
ก่อนเรียกฟังก์ชัน: number = 10
ในฟังก์ชัน:      x = 20
หลังเรียกฟังก์ชัน:  number = 10
```

**สังเกตให้ชัดเจน**: แม้ `x` จะถูกเปลี่ยนเป็น 20 ในฟังก์ชัน `try_to_double` แต่ `number` ใน
`main()` ยังคงเป็น 10 เหมือนเดิมทุกประการ เพราะ `x` เป็นเพียง **สำเนา** ของค่า `number`
ที่ถูกสร้างขึ้นใหม่ในหน่วยความจำคนละตำแหน่งกัน การเปลี่ยนแปลง `x` จึงไม่มีผลย้อนกลับไปที่
`number` เลย

### แผนภาพอธิบายหน่วยความจำ

```
main()                              try_to_double()
┌─────────────────┐                 ┌─────────────────┐
│ number = 10      │  --- copy -->  │ x = 10 (สำเนา)   │
│ (address: 0x1000) │                 │ (address: 0x2000) │
└─────────────────┘                 └─────────────────┘
                                      x = x * 2  →  x = 20
                                      (เปลี่ยนแค่ในกล่องนี้)

หลังฟังก์ชันจบ: number ที่ 0x1000 ยังเป็น 10 เหมือนเดิม เพราะเป็นคนละตำแหน่งหน่วยความจำกัน
```

นี่คือกฎที่ **สำคัญที่สุดข้อหนึ่งของภาษา C** และเป็นจุดที่มือใหม่สับสนบ่อยที่สุด: **ฟังก์ชัน
ไม่มีทางแก้ไขค่าตัวแปรที่อยู่นอกตัวมันเองได้โดยตรง** ไม่ว่าพารามิเตอร์จะเป็นชนิดข้อมูลพื้นฐาน
แบบไหนก็ตาม (`int`, `double`, `char`, ฯลฯ)

## 6.3 Return Value และฟังก์ชันแบบ void (Step 43)

ฟังก์ชันสามารถ "คืนค่า" กลับไปให้จุดที่เรียกใช้ได้ผ่านคำสั่ง `return` ชนิดของค่าที่คืนต้องตรงกับ
ชนิดที่ประกาศไว้หน้าชื่อฟังก์ชัน หากฟังก์ชันไม่ต้องการคืนค่าอะไรเลย ให้ใช้ชนิด `void`

```c
/*
 * return_demo.c
 * ตัวอย่างฟังก์ชันที่คืนค่า และฟังก์ชันแบบ void ที่ไม่คืนค่า
 */
#include <stdio.h>

int square(int n);              // คืนค่า int
double average(double a, double b, double c);   // คืนค่า double
void print_separator(void);     // ไม่คืนค่าอะไรเลย (void)

int main(void) {
    print_separator();
    printf("square(5) = %d\n", square(5));
    printf("average(4, 8, 9) = %.2f\n", average(4, 8, 9));
    print_separator();

    return 0;
}

int square(int n) {
    return n * n;                // return ทำให้ฟังก์ชันจบการทำงานทันที พร้อมส่งค่ากลับ
}

double average(double a, double b, double c) {
    return (a + b + c) / 3.0;
}

void print_separator(void) {
    printf("========================\n");
    // ฟังก์ชัน void ไม่จำเป็นต้องมี return แต่จะใส่ `return;` เปล่าๆ เพื่อออกก่อนกำหนดก็ได้
}
```

### return หลายจุดในฟังก์ชันเดียว

ฟังก์ชันสามารถมี `return` ได้หลายจุด เพื่อออกจากฟังก์ชันทันทีเมื่อเจอเงื่อนไขที่ต้องการ
(เทคนิคนี้เรียกว่า **Early Return** ช่วยลดการซ้อนเงื่อนไข `if-else` ลึกๆ ทำให้โค้ดอ่านง่ายขึ้น)

```c
/*
 * classify_number.c
 * ตัวอย่าง Early Return: จำแนกประเภทของตัวเลข
 */
#include <stdio.h>

const char *classify(int n);

int main(void) {
    printf("classify(-5) = %s\n", classify(-5));
    printf("classify(0)  = %s\n", classify(0));
    printf("classify(7)  = %s\n", classify(7));

    return 0;
}

const char *classify(int n) {
    if (n < 0) {
        return "ลบ";           // เจอเงื่อนไขแรก คืนค่าแล้วออกจากฟังก์ชันทันที ไม่ต้องเช็คต่อ
    }
    if (n == 0) {
        return "ศูนย์";
    }
    return "บวก";               // ถ้าไม่ตรงเงื่อนไขไหนเลย แปลว่าต้องเป็นค่าบวก
}
```

> หมายเหตุ: ฟังก์ชันนี้คืนค่าเป็น `const char *` (พอยเตอร์ชี้ไปยัง string literal) เรื่อง
> Pointer และ String อย่างละเอียดจะอยู่ใน Part 7-9 ตอนนี้ให้เข้าใจแค่ว่ามันคือการคืนค่าข้อความ
> กลับไปได้เช่นเดียวกับการคืนค่าตัวเลข

## 6.4 เกริ่นนำ: จำลอง Pass by Reference ด้วย Pointer (Step 44)

จากหัวข้อ 6.2 เราเห็นแล้วว่าฟังก์ชันแก้ไขตัวแปรต้นฉบับโดยตรงไม่ได้ (Pass by Value เท่านั้น)
แล้วถ้าต้องการให้ฟังก์ชันแก้ไขค่าตัวแปรจริงๆ ล่ะ เช่น ฟังก์ชันสลับค่าตัวแปร 2 ตัว (`swap`)?
คำตอบคือ **ส่ง Address (ที่อยู่ในหน่วยความจำ) ของตัวแปรเข้าไปแทนที่จะส่งค่าตรงๆ** ผ่านกลไก
ที่เรียกว่า **Pointer**

```c
/*
 * swap_demo.c
 * ตัวอย่างการจำลอง pass by reference ด้วย pointer เพื่อสลับค่าตัวแปร
 * (รายละเอียดเชิงลึกเรื่อง Pointer อยู่ใน Part 8-9)
 */
#include <stdio.h>

void swap(int *a, int *b);      // รับ "ที่อยู่" ของตัวแปร ไม่ใช่รับค่าตรงๆ

int main(void) {
    int x = 1;
    int y = 2;

    printf("ก่อนสลับ: x = %d, y = %d\n", x, y);
    swap(&x, &y);                // ส่ง address ของ x และ y เข้าไปด้วย & (address-of operator)
    printf("หลังสลับ: x = %d, y = %d\n", x, y);

    return 0;
}

void swap(int *a, int *b) {
    int temp = *a;    // *a คือ "ค่าที่อยู่ ณ address ที่ a ชี้ไปหา" (dereference)
    *a = *b;
    *b = temp;
}
```

ผลลัพธ์:

```
ก่อนสลับ: x = 1, y = 2
หลังสลับ: x = 2, y = 1
```

**ทำไมครั้งนี้ค่าถึงเปลี่ยนจริง?** เพราะสิ่งที่ถูกส่งเข้าไปในฟังก์ชัน `swap` ไม่ใช่ค่า `1`
หรือ `2` ตรงๆ แต่เป็น **address (ที่อยู่ในหน่วยความจำ)** ของตัวแปร `x` และ `y` ฟังก์ชันจึง
สามารถ "ตามไปหา" ตำแหน่งนั้นแล้วแก้ไขค่าที่แท้จริงได้ผ่านตัวดำเนินการ `*` (dereference)

สรุปสั้นๆ สำหรับตอนนี้ (จะอธิบายลึกกว่านี้มากใน Part 8):

- `int *a` หมายถึง `a` เป็นตัวแปรที่เก็บ **address** ของตัวแปร `int` อีกตัวหนึ่ง (เรียกว่า Pointer)
- `&x` หมายถึง "เอา address ของ `x`" (Address-of Operator)
- `*a` หมายถึง "เอาค่าที่ address ที่ `a` ชี้ไปหา" (Dereference Operator)

> **สิ่งสำคัญที่ต้องเข้าใจ**: ภาษา C **ไม่มี** Pass by Reference จริงๆ เหมือนภาษาอื่น (เช่น
> `int&` ใน C++) มีแต่ **Pass by Value ของ Address** เท่านั้น — เราแค่ส่ง "ค่า" ของ address
> เข้าไป ซึ่งบังเอิญทำให้ฟังก์ชันสามารถตามไปแก้ไขข้อมูลต้นทางได้ นี่คือความแตกต่างเชิงแนวคิด
> ที่สำคัญมาก และจะเข้าใจได้ชัดเจนที่สุดเมื่อเรียน Pointer อย่างละเอียดใน Part 8-9

## 6.5 Recursion เบื้องต้น: Factorial (Step 45)

**Recursion (การเรียกซ้ำตัวเอง)** คือเทคนิคที่ฟังก์ชันเรียกตัวมันเองภายในนิยามของมัน
ฟังไว้อาจดูงงในตอนแรก แต่เป็นเครื่องมือที่ทรงพลังมากสำหรับแก้ปัญหาที่มีโครงสร้างแบบ
"ปัญหาใหญ่ = ปัญหาเล็กแบบเดียวกัน + ขั้นตอนเพิ่มเติมเล็กน้อย"

ทุกฟังก์ชัน Recursive ต้องมี 2 ส่วนเสมอ **ไม่เช่นนั้นจะวนไม่รู้จบ**:

1. **Base Case (กรณีฐาน)** — เงื่อนไขที่ทำให้ฟังก์ชันหยุดเรียกตัวเองและคืนค่าออกมาตรงๆ
2. **Recursive Case (กรณีเรียกซ้ำ)** — เงื่อนไขที่ฟังก์ชันเรียกตัวเองด้วยปัญหาที่ "เล็กลง"

### ตัวอย่าง: Factorial ด้วย Recursion

ทางคณิตศาสตร์ `n! = n × (n-1) × (n-2) × ... × 1` และนิยามว่า `0! = 1`
สามารถเขียนแบบ Recursive ได้ว่า `n! = n × (n-1)!` โดยมี Base Case คือ `0! = 1`

```c
/*
 * factorial_recursive.c
 * คำนวณ n! ด้วยฟังก์ชัน Recursive
 */
#include <stdio.h>

long factorial(int n);

int main(void) {
    for (int i = 0; i <= 10; i++) {
        printf("%d! = %ld\n", i, factorial(i));
    }
    return 0;
}

long factorial(int n) {
    if (n <= 1) {
        return 1;                  // Base Case: 0! และ 1! เท่ากับ 1 เสมอ
    }
    return n * factorial(n - 1);   // Recursive Case: n! = n * (n-1)!
}
```

ผลลัพธ์ (บางส่วน):

```
0! = 1
1! = 1
2! = 2
3! = 6
4! = 24
5! = 120
...
10! = 3628800
```

### วิธีคิดตามลำดับการเรียก (Trace) สำหรับ `factorial(4)`

```
factorial(4)
  = 4 * factorial(3)
           = 3 * factorial(2)
                    = 2 * factorial(1)
                             = 1                    <-- Base Case ถึงแล้ว หยุดเรียกซ้ำ
                    = 2 * 1 = 2
           = 3 * 2 = 6
  = 4 * 6 = 24
```

จะสังเกตได้ว่าฟังก์ชันจะ "เรียกลึกลงไปเรื่อยๆ" จนกว่าจะถึง Base Case แล้วค่อย "คลี่กลับขึ้นมา"
คูณค่าจากล่างขึ้นบนจนได้คำตอบสุดท้าย

## 6.6 Recursion ขั้นถัดไป: Fibonacci และ Call Stack (Step 46)

**Fibonacci Sequence** คือลำดับตัวเลข 0, 1, 1, 2, 3, 5, 8, 13, 21, ... ซึ่งแต่ละตัวเท่ากับ
ผลรวมของ 2 ตัวก่อนหน้า นิยามทางคณิตศาสตร์คือ `F(n) = F(n-1) + F(n-2)` โดยมี Base Case
คือ `F(0) = 0` และ `F(1) = 1`

```c
/*
 * fibonacci_recursive.c
 * คำนวณลำดับ Fibonacci ด้วย Recursion
 */
#include <stdio.h>

long fibonacci(int n);

int main(void) {
    printf("ลำดับ Fibonacci ตั้งแต่ F(0) ถึง F(10):\n");
    for (int i = 0; i <= 10; i++) {
        printf("F(%d) = %ld\n", i, fibonacci(i));
    }
    return 0;
}

long fibonacci(int n) {
    if (n == 0) {
        return 0;                              // Base Case 1
    }
    if (n == 1) {
        return 1;                              // Base Case 2
    }
    return fibonacci(n - 1) + fibonacci(n - 2); // Recursive Case
}
```

ผลลัพธ์:

```
ลำดับ Fibonacci ตั้งแต่ F(0) ถึง F(10):
F(0) = 0
F(1) = 1
F(2) = 1
F(3) = 2
F(4) = 3
F(5) = 5
F(6) = 8
F(7) = 13
F(8) = 21
F(9) = 34
F(10) = 55
```

สังเกตว่า Fibonacci ต่างจาก Factorial ตรงที่มันเรียกตัวเอง **2 ครั้ง** ในแต่ละขั้น
(`fibonacci(n-1)` และ `fibonacci(n-2)`) ทำให้จำนวนการเรียกฟังก์ชันเพิ่มขึ้นแบบทวีคูณอย่างรวดเร็ว
เมื่อ `n` มีค่ามาก (ปัญหาด้านประสิทธิภาพนี้จะพูดถึงลึกๆ พร้อมวิธีแก้ด้วย Dynamic Programming
ใน Part 25)

### Call Stack คืออะไร และทำงานอย่างไรเบื้องหลัง Recursion

ทุกครั้งที่ฟังก์ชันถูกเรียก (ไม่ว่าจะเป็น Recursion หรือไม่ก็ตาม) ระบบปฏิบัติการจะจอง
หน่วยความจำก้อนเล็กๆ ที่เรียกว่า **Stack Frame** ไว้เก็บข้อมูลของการเรียกครั้งนั้น เช่น
ค่าพารามิเตอร์ ตัวแปร local และ "ที่อยู่ที่ต้องกลับไปทำงานต่อ" เมื่อฟังก์ชันนั้นจบลง
Stack Frame เหล่านี้จะถูกวางซ้อนกันเป็นกอง (Stack) ตามลำดับการเรียก เรียกว่า **Call Stack**

```
เรียก fibonacci(3):

┌─────────────────────┐  <- บนสุดของ stack (เรียกล่าสุด)
│ fibonacci(1)         │     กำลังรอ base case คืนค่า 1
├─────────────────────┤
│ fibonacci(2)         │     กำลังรอ fibonacci(1) + fibonacci(0)
├─────────────────────┤
│ fibonacci(3)         │     กำลังรอ fibonacci(2) + fibonacci(1)
├─────────────────────┤
│ main()               │     จุดเริ่มต้นของโปรแกรม
└─────────────────────┘  <- ล่างสุดของ stack
```

เมื่อฟังก์ชันที่อยู่บนสุดทำงานเสร็จ (ถึง Base Case แล้ว) Stack Frame ของมันจะถูก **pop**
(เอาออก) จาก stack แล้วค่าที่คืนกลับจะถูกส่งไปให้ฟังก์ชันที่เรียกมัน (อยู่ชั้นล่างถัดไป)
กระบวนการนี้ดำเนินไปเรื่อยๆ จนกว่า stack จะกลับมาเหลือแค่ `main()` เพียงอย่างเดียว

### เมื่อไม่มี Base Case: Stack Overflow

```c
/* ห้ามรันจริง! ตัวอย่างเพื่อการศึกษาเท่านั้น */
long broken_recursion(int n) {
    return n * broken_recursion(n - 1);   // ไม่มี Base Case เลย! เรียกตัวเองไม่มีที่สิ้นสุด
}
```

ฟังก์ชันนี้จะเรียกตัวเองไปเรื่อยๆ ไม่มีวันหยุด ทำให้ Call Stack ถูกจองหน่วยความจำเพิ่มขึ้น
ทุกครั้งที่เรียก จนกระทั่ง **หน่วยความจำสำหรับ Stack เต็ม** (Stack มีขนาดจำกัด ต่างจาก Heap
ที่จะเรียนใน Part 11) โปรแกรมจะ Crash ทันทีด้วย Error ที่เรียกว่า **Stack Overflow**
(บน Linux มักเห็นข้อความ `Segmentation fault (core dumped)`)

> **กฎเหล็กของ Recursion**: ฟังก์ชัน Recursive ทุกตัว **ต้องมี Base Case ที่ไปถึงได้จริง**
> และทุกการเรียกซ้ำต้องทำให้ปัญหา "เล็กลง" เข้าใกล้ Base Case มากขึ้นเสมอ (เช่น `n - 1` ต้อง
> ทำให้ `n` ลดลงจริง ไม่ใช่เพิ่มขึ้นหรือเท่าเดิม) ก่อนเขียน Recursive Function ทุกครั้ง
> ให้ถามตัวเองว่า "Base Case ของฟังก์ชันนี้คืออะไร และมั่นใจแค่ไหนว่าจะไปถึงมันได้เสมอ"

### Recursion vs Loop: เลือกใช้แบบไหนดี

| ประเด็น | Recursion | Loop |
|---|---|---|
| ความอ่านง่ายสำหรับปัญหาบางประเภท | ชัดเจนมาก (เช่น Tree, Divide-and-Conquer) | อาจซับซ้อนกว่าถ้าปัญหาซ้อนกันหลายชั้น |
| การใช้หน่วยความจำ | ใช้ Call Stack เพิ่มทุกการเรียก | ใช้หน่วยความจำคงที่ ไม่เพิ่มตามจำนวนรอบ |
| ความเร็ว | ช้ากว่าเล็กน้อยจาก overhead การเรียกฟังก์ชัน | เร็วกว่าโดยทั่วไป |
| ความเสี่ยง | Stack Overflow ถ้าลึกเกินไปหรือไม่มี Base Case | Infinite Loop ถ้าเงื่อนไขผิด |

ในทางปฏิบัติ ทุกปัญหาที่แก้ด้วย Recursion สามารถแปลงเป็น Loop ได้เสมอ (และในทางกลับกันก็จริง)
การเลือกใช้จึงขึ้นอยู่กับว่าแบบไหนทำให้โค้ด **สื่อความหมายชัดเจนที่สุด** สำหรับปัญหานั้นๆ

## 6.7 Scope: Local และ Global Variable (Step 47)

**Scope** คือขอบเขตที่ตัวแปรหนึ่งๆ "มองเห็นได้" และใช้งานได้ในโปรแกรม ภาษา C แบ่งเป็น
2 ระดับหลักที่ต้องเข้าใจตอนนี้:

- **Local Variable** — ตัวแปรที่ประกาศภายในฟังก์ชัน (หรือภายใน block `{ }` ใดๆ) มีชีวิตอยู่
  แค่ตอนที่ฟังก์ชัน/block นั้นทำงานอยู่เท่านั้น เมื่อฟังก์ชันจบ ตัวแปรจะถูกทำลายทิ้งทันที
- **Global Variable** — ตัวแปรที่ประกาศไว้นอกฟังก์ชันใดๆ ทั้งสิ้น (มักไว้ท้ายๆ ส่วน include
  ก่อน `main()`) มองเห็นได้จากทุกฟังก์ชันในไฟล์ และมีชีวิตอยู่ตลอดการทำงานของโปรแกรม

```c
/*
 * scope_demo.c
 * เปรียบเทียบ Local Variable กับ Global Variable
 */
#include <stdio.h>

int global_counter = 0;         // Global Variable: มองเห็นได้จากทุกฟังก์ชันในไฟล์นี้

void increment_and_show(void);

int main(void) {
    int local_value = 100;      // Local Variable: มองเห็นได้แค่ใน main() เท่านั้น

    printf("main: local_value = %d, global_counter = %d\n", local_value, global_counter);

    increment_and_show();
    increment_and_show();
    increment_and_show();

    printf("main: global_counter หลังเรียก 3 ครั้ง = %d\n", global_counter);
    // printf("%d", x);   // ถ้าเปิดบรรทัดนี้จะ compile error: x ไม่มีอยู่ใน scope ของ main

    return 0;
}

void increment_and_show(void) {
    int x = 5;                  // Local Variable ของฟังก์ชันนี้เท่านั้น ไม่รู้จัก local_value ของ main
    global_counter++;           // แก้ไข global variable ได้โดยตรงจากทุกฟังก์ชัน
    printf("increment_and_show: x = %d, global_counter = %d\n", x, global_counter);
}
```

ผลลัพธ์:

```
main: local_value = 100, global_counter = 0
increment_and_show: x = 5, global_counter = 1
increment_and_show: x = 5, global_counter = 2
increment_and_show: x = 5, global_counter = 3
main: global_counter หลังเรียก 3 ครั้ง = 3
```

### ทำไมควรหลีกเลี่ยง Global Variable ให้มากที่สุด

Global Variable ดูสะดวกในตอนแรก (ไม่ต้องส่งพารามิเตอร์ไปมา) แต่มีข้อเสียร้ายแรงเมื่อโปรแกรม
ใหญ่ขึ้น:

1. **ตามรอยบั๊กยาก** — ทุกฟังก์ชันแก้ไขมันได้ ถ้าค่าผิดเพี้ยน ต้องไล่เช็คทุกฟังก์ชันในไฟล์
2. **ทดสอบยาก** — ฟังก์ชันที่พึ่งพา Global Variable ทดสอบแยกเดี่ยวๆ ได้ยาก เพราะผลลัพธ์ขึ้นกับ
   สถานะภายนอกที่มองไม่เห็นจากการเรียกฟังก์ชันตรงๆ
3. **อันตรายเมื่อเขียนโปรแกรมแบบ Multi-threading** — หลาย thread แก้ไข Global Variable
   พร้อมกันจะเกิด Race Condition (จะเรียนเรื่องนี้ลึกๆ ใน Part 32)

> **แนวทางที่ดี**: ใช้ Local Variable และส่งค่าผ่านพารามิเตอร์/return value ให้มากที่สุด
> เก็บ Global Variable ไว้ใช้เฉพาะกรณีจำเป็นจริงๆ เช่น ค่าคงที่ระดับโปรแกรม (มักประกาศคู่กับ
> `const`) ไม่ใช่ตัวแปรที่เปลี่ยนแปลงบ่อยๆ

## 6.8 Storage Class: auto, static, extern, register (Step 48)

นอกจาก Scope แล้ว ตัวแปรในภาษา C ยังมีคุณสมบัติที่เรียกว่า **Storage Class** ซึ่งกำหนดว่า
ตัวแปรนั้นมี **อายุการใช้งาน (Lifetime)** และ **การมองเห็นข้ามไฟล์ (Linkage)** อย่างไร
C มี Storage Class Specifier 4 แบบหลัก:

| Storage Class | Lifetime | Scope/Linkage เริ่มต้น | ใช้เมื่อไร |
|---|---|---|---|
| `auto` | ตลอดที่ block ทำงานอยู่ | Local เท่านั้น | ค่า default ของตัวแปร local (แทบไม่เคยเขียนคำนี้ตรงๆ) |
| `static` (ใน function) | ตลอดการทำงานของโปรแกรม | Local (แต่ค่าคงอยู่ข้ามการเรียกฟังก์ชัน) | เก็บสถานะข้ามการเรียกฟังก์ชันแต่ละครั้ง |
| `static` (ระดับไฟล์/global) | ตลอดการทำงานของโปรแกรม | มองเห็นได้แค่ในไฟล์นี้ (Internal Linkage) | ซ่อนตัวแปร/ฟังก์ชันไม่ให้ไฟล์อื่นเห็น |
| `extern` | ตลอดการทำงานของโปรแกรม | มองเห็นข้ามไฟล์ได้ (External Linkage) | ใช้ตัวแปร/ฟังก์ชัน global ที่นิยามไว้ในไฟล์อื่น |
| `register` | ตลอดที่ block ทำงานอยู่ | Local เท่านั้น | ขอให้ compiler พิจารณาเก็บใน CPU register (ปัจจุบันแทบไม่จำเป็นแล้ว) |

### `auto` — ค่าเริ่มต้นที่ไม่ต้องเขียน

ตัวแปร local ทุกตัวที่เราเขียนมาตลอด (เช่น `int x = 5;` ในฟังก์ชัน) จริงๆ แล้วมี storage
class เป็น `auto` โดย default อยู่แล้ว การเขียน `auto int x = 5;` ตรงๆ นั้นถูกต้องตามไวยากรณ์
แต่**ไม่มีใครเขียนแบบนี้ในทางปฏิบัติ** เพราะมันคือค่า default อยู่แล้ว (หมายเหตุ: ใน C++11
ขึ้นไป คำว่า `auto` ถูกนำไปใช้ความหมายใหม่คือ Type Inference ซึ่งจะเรียนใน Part 69)

### `static` ในฟังก์ชัน — จำค่าข้ามการเรียกแต่ละครั้ง

นี่คือการใช้ `static` ที่มีประโยชน์และพบบ่อยที่สุด ตัวแปรที่ประกาศเป็น `static` ภายในฟังก์ชัน
จะถูกสร้างขึ้น **เพียงครั้งเดียว** ตลอดทั้งโปรแกรม และ **ค่าของมันจะไม่ถูกรีเซ็ตทุกครั้งที่
ฟังก์ชันถูกเรียกใหม่** ต่างจากตัวแปร local ธรรมดาที่ถูกสร้างใหม่ (และค่าถูกรีเซ็ต) ทุกครั้ง

```c
/*
 * static_counter.c
 * เปรียบเทียบตัวแปร local ธรรมดา กับตัวแปร static ภายในฟังก์ชัน
 */
#include <stdio.h>

void call_counter(void);

int main(void) {
    for (int i = 0; i < 5; i++) {
        call_counter();
    }
    return 0;
}

void call_counter(void) {
    int normal_count = 0;         // ถูกสร้างใหม่และรีเซ็ตเป็น 0 ทุกครั้งที่ฟังก์ชันถูกเรียก
    static int static_count = 0;  // ถูกสร้างครั้งเดียว ค่าคงอยู่ข้ามการเรียกแต่ละครั้ง

    normal_count++;
    static_count++;

    printf("normal_count = %d, static_count = %d\n", normal_count, static_count);
}
```

ผลลัพธ์:

```
normal_count = 1, static_count = 1
normal_count = 1, static_count = 2
normal_count = 1, static_count = 3
normal_count = 1, static_count = 4
normal_count = 1, static_count = 5
```

จะเห็นว่า `normal_count` เป็น `1` เสมอทุกครั้ง (เพราะถูกสร้างใหม่และตั้งค่าใหม่ทุกรอบ) ในขณะที่
`static_count` เพิ่มขึ้นเรื่อยๆ เพราะมันถูกสร้างขึ้นเพียงครั้งเดียวตอนโปรแกรมเริ่มทำงาน
และ "จำ" ค่าล่าสุดไว้ข้ามการเรียกฟังก์ชันแต่ละครั้ง

> ตัวอย่างการใช้งานจริง: ฟังก์ชันสุ่มเลข (`rand()`) ภายในต้องใช้ `static` เก็บสถานะ (seed)
> ไว้ข้ามการเรียกแต่ละครั้ง เพื่อให้สุ่มค่าใหม่ทุกครั้งที่เรียก ไม่ใช่ค่าเดิมซ้ำๆ

### `static` ระดับไฟล์ — จำกัดขอบเขตการมองเห็นให้อยู่แค่ไฟล์เดียว

เมื่อใช้กับตัวแปร global หรือฟังก์ชัน (นอก function body ใดๆ) คำว่า `static` จะมีความหมาย
ต่างออกไป: มันจะทำให้ตัวแปร/ฟังก์ชันนั้น **มองเห็นได้แค่ในไฟล์ `.c` นี้เท่านั้น** ไฟล์อื่นใน
โปรเจกต์เดียวกันจะไม่สามารถเรียกใช้ได้เลย (เรียกว่า Internal Linkage) มีประโยชน์มากสำหรับ
"ซ่อน" รายละเอียดภายในที่ไม่ต้องการให้ไฟล์อื่นยุ่งเกี่ยว (รายละเอียดเชิงลึกเรื่องการแบ่งไฟล์
และ Linkage จะอยู่ใน Part 17)

```c
/* file1.c */
static int internal_helper_value = 42;   // ไฟล์อื่นมองไม่เห็นตัวแปรนี้เลย

static void internal_helper(void) {      // ไฟล์อื่นเรียกฟังก์ชันนี้ไม่ได้เลย
    printf("ค่าภายใน: %d\n", internal_helper_value);
}
```

### `extern` — ประกาศว่าตัวแปร/ฟังก์ชันนี้นิยามไว้ที่ไฟล์อื่น

`extern` ใช้เมื่อต้องการเรียกใช้ตัวแปรหรือฟังก์ชัน global ที่ **นิยามจริงอยู่ในไฟล์ `.c`
อีกไฟล์หนึ่ง** เป็นการบอก compiler ว่า "ตัวแปรนี้มีอยู่จริง แค่ไม่ได้นิยามในไฟล์นี้ ไปหามัน
ตอน linking" (จะเห็นการใช้งานเต็มรูปแบบเมื่อเริ่มแบ่งโปรแกรมเป็นหลายไฟล์ใน Part 17)

```c
/* config.c */
int max_users = 100;              // นิยามตัวแปร global จริงที่นี่ (มีแค่ที่เดียวในโปรแกรม)
```

```c
/* main.c */
extern int max_users;             // ประกาศว่า "ตัวแปรนี้มีอยู่จริงในไฟล์อื่น" ไม่ใช่การสร้างใหม่

#include <stdio.h>

int main(void) {
    printf("จำนวนผู้ใช้สูงสุด: %d\n", max_users);   // ใช้งานได้ปกติ เพราะ Linker หาให้เจอ
    return 0;
}
```

### `register` — คำขอร้อง compiler (ที่แทบไม่จำเป็นแล้วในปัจจุบัน)

`register` เป็นคำสั่งบอก compiler ว่า "ช่วยพิจารณาเก็บตัวแปรนี้ไว้ใน CPU register แทน RAM
เพื่อความเร็วในการเข้าถึง" ในยุคที่ compiler ยังไม่ฉลาดมาก (ทศวรรษ 1970-1980) คำสั่งนี้
มีประโยชน์จริง แต่ **compiler สมัยใหม่ (GCC, Clang) ฉลาดกว่าโปรแกรมเมอร์มากในการตัดสินใจ
เรื่องนี้เอง** ทำให้ `register` แทบไม่มีผลอะไรในทางปฏิบัติแล้วในปี 2026 (compiler มีสิทธิ์
เพิกเฉยต่อคำขอนี้ได้เสมอ เพราะเป็นเพียง "hint" ไม่ใช่คำสั่งบังคับ)

```c
void sum_array(void) {
    register int i;              // เพียงคำแนะนำ compiler อาจเก็บใน register หรือไม่ก็ได้
    long sum = 0;
    int data[5] = {1, 2, 3, 4, 5};

    for (i = 0; i < 5; i++) {
        sum += data[i];
    }
    printf("sum = %ld\n", sum);
}
```

> ข้อควรทราบ: ตัวแปรที่ประกาศเป็น `register` **ห้ามนำ address มาใช้** (คือห้ามใช้ `&i`)
> เพราะถ้าตัวแปรถูกเก็บใน register จริง มันจะไม่มี address ในหน่วยความจำแบบปกติให้ชี้ไปหา
> ในทางปฏิบัติปัจจุบัน แนะนำให้ปล่อยให้ compiler ตัดสินใจเรื่อง optimization เอง และเขียน
> ตัวแปรแบบธรรมดาโดยไม่ต้องใส่ `register` เลย

## ข้อผิดพลาดที่พบบ่อย (Common Pitfalls)

1. **คาดหวังว่าฟังก์ชันจะแก้ไขตัวแปรต้นฉบับได้โดยไม่ใช้ Pointer** — เป็นความเข้าใจผิดที่พบ
   บ่อยที่สุดของ Part นี้ จำไว้เสมอว่า C ส่งพารามิเตอร์แบบ Pass by Value เท่านั้น ถ้าต้องการ
   แก้ไขค่าต้นฉบับจริงๆ ต้องส่ง address เข้าไป (ดูหัวข้อ 6.4)

2. **ลืมเขียน Function Prototype** ทำให้เกิด `error: implicit declaration of function` เมื่อ
   เรียกใช้ฟังก์ชันก่อนที่ compiler จะเห็น definition ของมัน

3. **Recursion ที่ไม่มี Base Case หรือ Base Case ที่ไปไม่ถึง** — ทำให้เกิด Stack Overflow
   และโปรแกรม Crash เช่น เขียน `factorial(n)` แต่ตรวจ `if (n == 0)` เพียงอย่างเดียว
   ถ้าผู้ใช้ป้อนเลขติดลบเข้ามา `n` จะลดลงเรื่อยๆ (`-1, -2, -3, ...`) โดยไม่มีวันเท่ากับ `0`
   พอดี ทำให้ไม่ถึง Base Case เลย

   ```c
   long factorial(int n) {
       if (n == 0) {              // บั๊ก: ถ้า n เป็นค่าลบ จะไม่มีวันเท่ากับ 0 พอดี
           return 1;
       }
       return n * factorial(n - 1);
   }
   ```

   วิธีแก้: ตรวจสอบและปฏิเสธ input ที่ไม่ถูกต้องตั้งแต่ก่อนเรียก recursion หรือใช้เงื่อนไข
   `if (n <= 1)` แทน `if (n == 0)` เพื่อความปลอดภัยเพิ่มขึ้น (ดังตัวอย่างในหัวข้อ 6.5)

4. **ใช้ Global Variable พร่ำเพรื่อแทนการส่งพารามิเตอร์** — ทำให้โค้ดติดตามยากและทดสอบยาก
   เมื่อโปรแกรมมีขนาดใหญ่ขึ้น (ดูเหตุผลละเอียดในหัวข้อ 6.7)

5. **สับสนระหว่าง `static` ในฟังก์ชัน กับ `static` ระดับไฟล์** — ทั้งสองใช้คำเดียวกันแต่ความหมาย
   ต่างกันโดยสิ้นเชิง (เก็บค่าข้ามการเรียก vs จำกัดขอบเขตการมองเห็นข้ามไฟล์) ต้องดูบริบทว่า
   ประกาศอยู่ที่ไหนเสมอ

6. **คืนค่า Address ของตัวแปร Local ออกจากฟังก์ชัน** — เป็นบั๊กอันตรายที่ compiler มักเตือน
   ให้ด้วย `-Wall`:

   ```c
   int *get_dangling_pointer(void) {
       int local_value = 42;
       return &local_value;    // อันตราย: คืน address ของตัวแปรที่กำลังจะถูกทำลายทิ้ง!
   }
   ```

   ```
   warning: function returns address of local variable [-Wreturn-local-addr]
   ```

   เมื่อฟังก์ชันจบการทำงาน `local_value` จะถูกทำลายทิ้งทันที (Stack Frame ถูก pop ออก)
   address ที่คืนกลับไปจึงชี้ไปยังหน่วยความจำที่ไม่ถูกต้องแล้ว (Dangling Pointer) การใช้งาน
   ค่าที่ได้จาก address นี้คือ Undefined Behavior — เรื่องนี้จะเข้าใจลึกซึ้งขึ้นมากหลังเรียน
   เรื่อง Pointer และ Stack Memory ใน Part 8-9 และ 26

## แบบฝึกหัดท้ายบท

1. เขียนฟังก์ชัน `int max_of_two(int a, int b)` ที่คืนค่าตัวเลขที่มากกว่าระหว่าง `a` และ `b`
   แล้วเรียกใช้จาก `main()` เพื่อหาค่าที่มากที่สุดจากตัวเลข 3 ตัวที่ผู้ใช้ป้อน (เรียกฟังก์ชัน
   นี้ 2 ครั้ง)

2. เขียนฟังก์ชัน `void swap_and_show(int *a, int *b)` ที่สลับค่าของตัวแปรที่ `a` และ `b`
   ชี้ไปหา แล้วพิมพ์ค่าทั้งสองหลังสลับออกมาทันทีภายในฟังก์ชันนั้นเลย

3. เขียนฟังก์ชัน Recursive ชื่อ `int sum_digits(int n)` ที่หาผลรวมของหลักตัวเลขทั้งหมดใน `n`
   เช่น `sum_digits(1234)` ต้องได้ `1 + 2 + 3 + 4 = 10` (คำใบ้: Base Case คือเมื่อ `n` มีแค่
   หลักเดียว Recursive Case คือ `n % 10 + sum_digits(n / 10)`)

4. เขียนฟังก์ชัน `int fibonacci_iterative(int n)` ที่คำนวณค่า Fibonacci ตัวที่ `n` **โดยใช้
   loop แทน Recursion** แล้วเปรียบเทียบความเร็วกับฟังก์ชัน Recursive ในหัวข้อ 6.6 เมื่อ
   `n = 35` (ใช้คำสั่ง `time ./program` วัดเวลา)

5. เขียนโปรแกรมที่มีฟังก์ชัน `void generate_id(void)` ใช้ตัวแปร `static` ภายในเพื่อสร้างเลข ID
   ที่เพิ่มขึ้นทีละ 1 ทุกครั้งที่ถูกเรียก (เริ่มจาก 1001) แล้วเรียกใช้ฟังก์ชันนี้ 5 ครั้งใน `main()`

6. อธิบายด้วยคำพูดของตัวเอง (เขียนเป็น comment ในโค้ด หรือเขียนแยกเป็นข้อความ) ว่าทำไมฟังก์ชัน
   ต่อไปนี้จึงเป็นอันตราย และควรแก้ไขอย่างไร

   ```c
   int *create_array_sum_pointer(void) {
       int result = 0;
       for (int i = 1; i <= 10; i++) {
           result += i;
       }
       return &result;
   }
   ```

### แนวทางเฉลยข้อ 3

```c
/*
 * sum_digits.c
 * หาผลรวมของหลักตัวเลขทั้งหมดใน n ด้วย Recursion
 */
#include <stdio.h>

int sum_digits(int n);

int main(void) {
    int number;

    printf("ป้อนตัวเลขที่ต้องการหาผลรวมของหลัก: ");
    if (scanf("%d", &number) != 1) {
        printf("รูปแบบข้อมูลไม่ถูกต้อง\n");
        return 1;
    }

    if (number < 0) {
        number = -number;   // แปลงเป็นค่าบวกก่อน เพื่อให้ % และ / ทำงานได้ตรงตามที่คาดหวัง
    }

    printf("ผลรวมของหลักใน %d คือ %d\n", number, sum_digits(number));

    return 0;
}

int sum_digits(int n) {
    if (n < 10) {
        return n;                          // Base Case: เหลือหลักเดียวแล้ว คืนค่าตรงๆ
    }
    return n % 10 + sum_digits(n / 10);    // Recursive Case: บวกหลักสุดท้าย + ผลรวมที่เหลือ
}
```

ตัวอย่างการรัน: ป้อน `1234` จะได้ `ผลรวมของหลักใน 1234 คือ 10`

ลอง trace การทำงานของ `sum_digits(1234)`:

```
sum_digits(1234) = 4 + sum_digits(123)
                       = 3 + sum_digits(12)
                              = 2 + sum_digits(1)
                                     = 1              <-- Base Case: n < 10
                              = 2 + 1 = 3
                       = 3 + 3 = 6
                = 4 + 6 = 10
```

### แนวทางเฉลยข้อ 5

```c
/*
 * generate_id.c
 * สร้างเลข ID ที่เพิ่มขึ้นทีละ 1 ทุกครั้งที่เรียกฟังก์ชัน โดยใช้ static variable
 */
#include <stdio.h>

void generate_id(void);

int main(void) {
    for (int i = 0; i < 5; i++) {
        generate_id();
    }
    return 0;
}

void generate_id(void) {
    static int next_id = 1001;   // ถูกสร้างและตั้งค่าเริ่มต้นแค่ครั้งเดียวตลอดโปรแกรม

    printf("ID ที่ออกให้: %d\n", next_id);
    next_id++;                   // ค่าจะถูกจำไว้ข้ามการเรียกครั้งถัดไปเสมอ
}
```

ผลลัพธ์:

```
ID ที่ออกให้: 1001
ID ที่ออกให้: 1002
ID ที่ออกให้: 1003
ID ที่ออกให้: 1004
ID ที่ออกให้: 1005
```

โค้ดนี้แสดงให้เห็นการใช้งานจริงของ `static` ภายในฟังก์ชัน: ฟังก์ชัน `generate_id` ไม่ต้องรับ
พารามิเตอร์ใดๆ เลย แต่ยังคง "จำ" สถานะล่าสุดของ ID ไว้ได้ข้ามการเรียกแต่ละครั้ง โดยไม่ต้องใช้
Global Variable นอกฟังก์ชันเลย ซึ่งปลอดภัยกว่าเพราะไม่มีฟังก์ชันอื่นสามารถเข้าถึงหรือแก้ไข
`next_id` ได้โดยตรงนอกจากผ่านฟังก์ชันนี้เท่านั้น

## สรุปท้ายบท

ใน Part นี้เราได้:

- เข้าใจว่าทำไมต้องแบ่งโปรแกรมเป็นฟังก์ชัน และความแตกต่างระหว่าง Prototype กับ Definition
- เข้าใจกลไก Pass by Value อย่างละเอียด และรู้ว่าทำไมฟังก์ชันแก้ไขตัวแปรต้นฉบับตรงๆ ไม่ได้
- เห็นภาพเบื้องต้นของการใช้ Pointer จำลอง Pass by Reference ผ่านตัวอย่าง `swap`
- เขียนฟังก์ชัน Recursive ได้ (Factorial, Fibonacci) พร้อมเข้าใจ Base Case และ Recursive Case
- เข้าใจกลไก Call Stack เบื้องหลัง Recursion และรู้จักอาการ Stack Overflow เมื่อไม่มี Base Case
- แยกแยะ Local Scope กับ Global Scope ได้ พร้อมเข้าใจข้อเสียของการใช้ Global Variable พร่ำเพรื่อ
- เลือกใช้ Storage Class ที่เหมาะสม (`auto`, `static`, `extern`, `register`) ตามสถานการณ์จริง

ฟังก์ชันคือกลไกสำคัญที่ทำให้เราจัดระเบียบโปรแกรมขนาดใหญ่ได้ แต่จนถึงตอนนี้เรายังทำงานกับ
