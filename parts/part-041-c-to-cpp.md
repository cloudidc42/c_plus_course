## 41.1 ประวัติศาสตร์ของ C++ และ Bjarne Stroustrup (Step 321)

ตลอด 40 Part ที่ผ่านมาเราใช้เวลาทั้งหมดอยู่กับภาษา C — ตั้งแต่ตัวแปรพื้นฐานไปจนถึงการสร้าง
TCP server แบบ multi-thread ด้วยมือเปล่า ถึงเวลาแล้วที่จะก้าวข้ามไปสู่ภาษาถัดไปในหลักสูตรนี้:
**C++**

### จุดเริ่มต้น: ปัญหาที่ Bjarne Stroustrup ต้องการแก้

ปี 1979 วิศวกรชาวเดนมาร์กชื่อ **Bjarne Stroustrup** ทำงานอยู่ที่ **Bell Labs** (ที่เดียวกับที่
Dennis Ritchie สร้างภาษา C และ Ken Thompson สร้าง Unix) เขากำลังทำวิจัยด้าน Distributed
Systems และต้องการเขียนโปรแกรมจำลองระบบที่ซับซ้อนมาก ปัญหาที่เขาเจอคือ:

- ภาษา **C** เร็วและใกล้ฮาร์ดแวร์ แต่ไม่มีเครื่องมือช่วยจัดระเบียบโปรแกรมขนาดใหญ่ที่มีข้อมูล
  และพฤติกรรมซับซ้อนหลายแบบปะปนกัน — ทุกอย่างต้องแยก struct กับฟังก์ชันออกจากกันเองด้วยมือ
  ทั้งหมด และไม่มีกลไกป้องกันคนอื่นเข้าถึง field ภายในของ struct โดยตรง (ทบทวนปัญหานี้จาก
  Part 40 ที่ต้องใช้เทคนิค Opaque Type แก้ปัญหาแบบ "เลี่ยงบาลี" เพราะ C ไม่มีกลไกนี้ในตัว)
- ภาษา **Simula67** (ภาษาสำหรับงานวิจัยด้าน simulation ที่ Stroustrup เคยใช้ตอนเรียนปริญญาเอก
  ที่เคมบริดจ์) มีแนวคิดเรื่อง **class** ที่ห่อหุ้มข้อมูลกับพฤติกรรมไว้ด้วยกันได้อย่างสวยงาม
  แต่ Simula67 ช้าเกินไปสำหรับงาน production จริง เพราะออกแบบมาเน้นความสะดวกในการวิจัยมากกว่า
  ประสิทธิภาพ

Stroustrup จึงตั้งเป้าหมายที่ชัดเจนมาก: **เอาแนวคิดเรื่อง class จาก Simula67 มาใส่ในภาษา C
โดยไม่เสียความเร็วและการควบคุมระดับต่ำของ C ไปแม้แต่นิดเดียว** เขาเริ่มพัฒนาสิ่งที่เรียกว่า
**"C with Classes"** ในปี 1979 ซึ่งในตอนแรกเป็นแค่ **Preprocessor** ที่แปลงโค้ดที่มี class
ให้กลายเป็นโค้ด C ธรรมดาก่อนส่งต่อให้ C compiler ทำงานต่อ (เทคนิคนี้เรียกว่า `cfront`)

### จาก "C with Classes" สู่ "C++"

ปี 1983 ภาษานี้ถูกเปลี่ยนชื่อเป็น **C++** โดยเพื่อนร่วมงานของ Stroustrup ชื่อ Rick Mascitti
ชื่อนี้เป็นมุกตลกของโปรแกรมเมอร์: `++` คือ **increment operator** ของภาษา C ที่ทุกคนรู้จักดี
ดังนั้น "C++" จึงแปลว่า **"C ที่เพิ่มขึ้นมาอีกหนึ่งขั้น"** — ชื่อที่สื่อความหมายได้ตรงตัวและ
เป็นที่จดจำมาก

หลักการออกแบบที่ Stroustrup ยึดถือมาตลอดตั้งแต่วันแรกจนถึงมาตรฐานล่าสุดคือ **"Zero-Overhead
Principle"**: ฟีเจอร์ใดๆ ที่เพิ่มเข้ามาใน C++ ต้อง **ไม่ทำให้โปรแกรมที่ไม่ได้ใช้ฟีเจอร์นั้นช้าลง
เลยแม้แต่นิดเดียว** เมื่อเทียบกับการเขียนโค้ดแบบ C ล้วนๆ ด้วยมือ พูดง่ายๆ คือ "จ่ายเฉพาะสิ่งที่ใช้"
(You only pay for what you use) — หลักการนี้คือเหตุผลที่ C++ ยังคงเป็นภาษาที่เร็วที่สุดภาษาหนึ่ง
ของโลกได้ แม้จะมีฟีเจอร์ระดับสูงมากมายกว่า C หลายเท่าตัวก็ตาม

### ทำไม C++ ยังสำคัญมากในปี 2026

เช่นเดียวกับที่ Part 1 อธิบายความสำคัญของ C ในโลกปัจจุบัน C++ ก็เป็นภาษาที่ยืนหยัดมาเกือบ
45 ปีและยังคงเป็นเสาหลักของอุตสาหกรรมซอฟต์แวร์:

- **Browser engines**: Chrome (V8 JavaScript Engine), Firefox (Gecko), Safari (WebKit) ล้วน
  เขียนด้วย C++ เป็นหลัก
- **Game engines**: Unreal Engine, Unity (core engine), Source Engine ของ Valve
- **ฐานข้อมูลระดับโลก**: MongoDB, MySQL, ClickHouse, และส่วนสำคัญของ PostgreSQL
- **Machine Learning frameworks**: PyTorch และ TensorFlow ทั้งคู่มี core computation engine
  เขียนด้วย C++ (ส่วน Python ที่นักวิจัย ML ใช้เป็นแค่ "เปลือก" ที่เรียก C++ ข้างในอีกที)
- **ระบบการเงินความเร็วสูง (High-Frequency Trading)**: แทบทั้งหมดเขียนด้วย C++ เพราะต้องการ
  latency ระดับ microsecond
- **Operating Systems และ Embedded**: Windows (ส่วนใหญ่), macOS (บางส่วน), Adobe Photoshop,
  ระบบควบคุมยานยนต์ไฟฟ้า, Firmware ของอุปกรณ์ที่ต้องการประสิทธิภาพสูงและควบคุมหน่วยความจำเอง

จุดที่ต้องเข้าใจให้ชัดตั้งแต่ต้น Module นี้: **C++ ไม่ได้มาแทนที่ C** ทั้งสองภาษายังถูกใช้งาน
คู่ขนานกันในโลกจริง — C เหมาะกับงานที่ต้องการความเรียบง่ายสุดขั้วและ portability สูงสุด (เช่น
Kernel, Firmware ขนาดเล็กมาก) ส่วน C++ เหมาะกับระบบขนาดใหญ่ที่ต้องจัดการความซับซ้อนสูง โดยยังคง
ประสิทธิภาพระดับเดียวกับ C ไว้ได้

## 41.2 ทำไม C++ ถึงทรงพลังกว่า C (Step 322)

Module A–C ทั้งหมดสอนให้เราเขียนโปรแกรมด้วยแนวคิดที่เรียกว่า **Procedural Programming**:
โปรแกรมคือลำดับของฟังก์ชันที่เรียกกันไปมา ทำงานกับข้อมูลที่แยกออกจากฟังก์ชันโดยสิ้นเชิง
(ทบทวน Part 40: `kv_store.h` มีทั้งฟังก์ชัน `kv_set`, `kv_get` และ struct `KVStore` แยกกันคนละ
ส่วน ผู้เรียกต้องส่ง `KVStore *` เข้าไปในทุกฟังก์ชันเอง) C++ เพิ่มแนวคิดใหม่ 4 เรื่องใหญ่ที่จะ
เปลี่ยนวิธีคิดในการออกแบบโปรแกรมไปอย่างสิ้นเชิงตลอดหลักสูตรที่เหลือ:

### 1. Object-Oriented Programming (OOP) — จะเรียนเจาะลึกใน Part 45–54

C++ อนุญาตให้ห่อข้อมูล (data) กับฟังก์ชันที่ทำงานกับข้อมูลนั้น (behavior) ไว้เป็นก้อนเดียวกัน
เรียกว่า **class** ต่างจาก Part 40 ที่ `KVStore` (ข้อมูล) กับ `kv_set`/`kv_get` (ฟังก์ชัน) เป็น
คนละสิ่งที่แยกจากกันโดยสมบูรณ์ ใน C++ เราจะเขียนได้ประมาณนี้ (ตัวอย่างคร่าวๆ เพื่อให้เห็นภาพ
รายละเอียดทั้งหมดจะเรียนใน Part 45 เป็นต้นไป):

```cpp
class KVStore {
public:
    bool set(const std::string &key, const std::string &value);
    std::string get(const std::string &key);
private:
    // ข้อมูลภายในถูกซ่อนไว้ในตัว class เอง ไม่ต้องพึ่ง Opaque Type แบบ Part 40 อีกต่อไป
};
```

สังเกตว่าไม่ต้องมี `KVStore *kv` ส่งเข้าไปในทุกฟังก์ชันอีกต่อไป เพราะข้อมูลกับฟังก์ชันเป็นเนื้อ
เดียวกันแล้ว — แนวคิดนี้เรียกว่า **Encapsulation** และเป็นรากฐานของ OOP ทั้งหมด

### 2. Generic Programming ด้วย Template — จะเรียนเจาะลึกใน Part 56–57 และ Module E ทั้งหมด

ใน C ถ้าต้องการเขียนฟังก์ชัน `max` ที่ใช้ได้กับทั้ง `int`, `double`, `float` ต้องเขียนแยกฟังก์ชัน
หรือใช้ Macro ที่ไม่ตรวจสอบชนิดข้อมูลเลย (ทบทวน Part 14) C++ มี **Template** ที่ให้คอมไพเลอร์
สร้างฟังก์ชันเฉพาะสำหรับแต่ละชนิดข้อมูลให้อัตโนมัติ โดยยังคงตรวจสอบชนิดข้อมูลอย่างเข้มงวด:

```cpp
template <typename T>
T my_max(T a, T b) {
    return (a > b) ? a : b;
}
```

เรียก `my_max(3, 5)` จะได้ `int`, เรียก `my_max(3.5, 2.1)` จะได้ `double` — โดยคอมไพเลอร์สร้าง
โค้ดเฉพาะให้แต่ละชนิดข้อมูล **ตอนคอมไพล์** ไม่มีค่าใช้จ่ายเพิ่มตอนรันโปรแกรมเลยแม้แต่นิดเดียว
(ตรงตาม Zero-Overhead Principle ที่อธิบายไปในหัวข้อก่อนหน้า)

### 3. RAII (Resource Acquisition Is Initialization) — จะเรียนเจาะลึกใน Part 46 และ 68

ทบทวนปัญหาที่เจอบ่อยที่สุดตลอด Module B–C: ลืม `free()`, ลืม `fclose()`, ลืม `pthread_mutex_
unlock()` เมื่อมี early return หรือเกิด error กลางทาง (Part 38 ทั้ง Part พูดถึงการใช้ Valgrind
ตามหาปัญหาเหล่านี้) C++ มีกลไกที่เรียกว่า **RAII**: ผูกการคืนทรัพยากรเข้ากับ **lifetime ของตัวแปร
โดยอัตโนมัติ** ผ่านกลไกที่เรียกว่า **destructor** — เมื่อตัวแปรหมดขอบเขต (ไม่ว่าจะจบฟังก์ชัน
ปกติ หรือมี exception เกิดขึ้นกลางทาง) ทรัพยากรที่ถืออยู่จะถูกคืนอัตโนมัติเสมอ ไม่มีทางลืมได้อีก
ต่อไป (เกริ่นนำใน Part 46 เจาะลึกเต็มรูปแบบใน Part 68)

### 4. Standard Template Library (STL) — จะเรียนเจาะลึกทั้ง Module E

Part 19–22 เราเขียน Linked List, Stack, Queue, Hash Table ด้วยมือทั้งหมดตั้งแต่ศูนย์ เพื่อให้
เข้าใจกลไกภายในอย่างลึกซึ้ง (ซึ่งเป็นสิ่งที่ถูกต้องและจำเป็นสำหรับการเรียนรู้) แต่ในงานจริงที่ต้อง
ส่งมอบผลิตภัณฑ์ ไม่มีใครเขียนโครงสร้างข้อมูลพื้นฐานเหล่านี้ใหม่ทุกโปรเจกต์ — C++ มาพร้อมกับ
**STL**: ชุดโครงสร้างข้อมูลและอัลกอริทึมมาตรฐานที่ผ่านการทดสอบและปรับแต่งประสิทธิภาพมาอย่างดี
เช่น `std::vector` (dynamic array), `std::unordered_map` (hash table แบบเดียวกับที่เขียนเองใน
Part 22 แต่ปรับแต่งประสิทธิภาพระดับ production) และอื่นๆ อีกมากมาย

### ตารางเปรียบเทียบสรุป

| แนวคิด | C (สิ่งที่เราทำใน Module A–C) | C++ (สิ่งที่จะเรียนต่อไป) |
|---|---|---|
| การจัดระเบียบข้อมูล+ฟังก์ชัน | แยกกัน (struct + ฟังก์ชันที่รับ struct*) | รวมกันเป็น `class` (Part 45+) |
| ซ่อนรายละเอียดภายใน | ใช้ Opaque Type แบบ "เลี่ยงบาลี" (Part 40) | มี `private`/`public` ในตัวภาษา (Part 47) |
| เขียนโค้ด generic กับหลายชนิดข้อมูล | Macro (ไม่ type-safe) หรือเขียนซ้ำ | Template (type-safe, Part 56) |
| จัดการทรัพยากร (memory, file, lock) | ต้อง `free`/`fclose`/`unlock` ด้วยมือทุกจุด | RAII: คืนอัตโนมัติตาม lifetime (Part 46, 68) |
| โครงสร้างข้อมูลพื้นฐาน | เขียนเองทั้งหมด (Part 19–22) | มี STL ให้ใช้ทันที (Module E) |
| การขยาย behavior ตามชนิดย่อย | Function pointer + switch-case ด้วยมือ | Inheritance + Virtual Function (Part 48–49) |

ทุกหัวข้อในคอลัมน์ขวาคือสิ่งที่เราจะเรียนตลอด Module D–E ของหลักสูตรนี้ Part นี้เป็นแค่จุดเริ่ม
ต้นที่ปูพื้นฐานภาษาให้พร้อมก่อนเจาะลึกแนวคิดใหญ่ๆ เหล่านี้

## 41.3 ติดตั้งและคอมไพล์ด้วย g++ (Step 323)

### ข่าวดี: ไม่ต้องติดตั้งอะไรเพิ่ม

ถ้าทำตาม Part 1 ติดตั้ง `build-essential` บน Linux/WSL ไว้แล้ว จะมี `g++` (GNU C++ Compiler)
ติดตั้งมาให้พร้อมกับ `gcc` อยู่แล้วโดยอัตโนมัติ ตรวจสอบได้ทันที:

```bash
g++ --version
```

C ใช้นามสกุล `.c` เท่านั้น แต่ C++ มีหลายนามสกุลที่ยอมรับกันในวงการ:

### อธิบายทีละบรรทัด (เทียบกับ `hello.c` จาก Part 1)

- **`#include <iostream>`**: ในภาษา C เราใช้ `<stdio.h>` สำหรับ I/O ส่วน C++ มีไลบรารี I/O
  ของตัวเองชื่อ `<iostream>` (**i**nput/**o**utput **stream**) — ทั้งสองไลบรารีทำงานคู่ขนานกัน
  ได้จริง (จะสาธิตให้เห็นในหัวข้อ 41.8) แต่ในโค้ด C++ สมัยใหม่ เราจะใช้ `<iostream>` เป็นหลัก
  รายละเอียดเชิงลึกของ stream และเหตุผลที่ต้องมี namespace `std::` จะอธิบายเต็มรูปแบบใน Part 42
- **`int main()`**: สังเกตว่าไม่มี `void` ในวงเล็บเหมือน `int main(void)` ใน C — **นี่คือความ
  แตกต่างสำคัญที่จะอธิบายละเอียดในหัวข้อ 41.5**: ใน C++ `main()` (วงเล็บว่างเปล่า) มีความหมาย
  เหมือนกับ `main(void)` ทุกประการ คือ "ไม่รับพารามิเตอร์ใดๆ" ต่างจาก C ที่ `main()` แปลว่า
  "ไม่ระบุพารามิเตอร์" (ยอมรับอะไรก็ได้แบบไม่ตรวจสอบ)
- **`std::cout << "Hello, C++!" << std::endl;`**: `std::cout` คือ object ที่แทน "ช่องทางส่งออก
  มาตรฐาน" (คู่กับ `stdout` ใน C) ตัวดำเนินการ `<<` เรียกว่า **stream insertion operator**
  ทำหน้าที่ "ส่งข้อมูลเข้าไปใน stream" — สามารถต่อกันได้หลายตัวในบรรทัดเดียว (**chaining**)
  ส่วน `std::endl` คือการขึ้นบรรทัดใหม่พร้อม flush buffer (รายละเอียดเทียบกับ `"\n"` จะอธิบาย
  เต็มรูปแบบใน Part 42)
- **`return 0;`**: ความหมายเหมือนกับ C ทุกประการ — คืน Exit Code กลับไปให้ระบบปฏิบัติการ

## 41.5 ความแตกต่างสำคัญ ตอนที่ 1: ประกาศตัวแปรได้ทุกที่ และ `bool` (Step 325)

จากหัวข้อนี้เป็นต้นไป เราจะไล่ดูความแตกต่างสำคัญระหว่าง C กับ C++ ทีละข้อ ที่ต้องรู้ทันทีตั้งแต่
วันแรกที่เขียน C++ เพราะจะเจอในทุกบรรทัดของโค้ดตลอดหลักสูตรที่เหลือ

### ความแตกต่างที่ 1: ประกาศตัวแปรได้ทุกที่ในฟังก์ชัน

ใน C89/ANSI C (มาตรฐานดั้งเดิม) กฎเข้มงวดมากคือ **ตัวแปรทุกตัวต้องประกาศไว้ต้นบล็อกเท่านั้น**
ก่อนคำสั่งอื่นใด (C99 เป็นต้นไปผ่อนปรนกฎนี้บ้างแล้ว แต่ยังมีข้อจำกัดกว่า C++ อยู่ดี) ส่วน C++
อนุญาตให้ **ประกาศตัวแปรตรงจุดที่ใช้งานครั้งแรกได้เลย** ไม่ว่าจะอยู่กลางฟังก์ชันตรงไหนก็ตาม:

```cpp
#include <iostream>

int main() {
    std::cout << "เริ่มโปรแกรม\n";

    for (int i = 0; i < 3; i++) {  // ประกาศ i ตรงจุดที่ใช้ครั้งแรกในหัว for ได้เลย
        std::cout << "รอบที่ " << i << '\n';
    }

    int total = 0;
    for (int i = 0; i < 5; i++) {
        total += i;
        int squared = i * i;  // ประกาศตัวแปรใหม่กลางฟังก์ชันได้ ไม่ต้องอยู่ต้นบล็อก
        std::cout << i << "^2 = " << squared << '\n';
    }

    std::cout << "total = " << total << '\n';
    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 declare_anywhere.cpp -o declare_anywhere
./declare_anywhere
```

```
เริ่มโปรแกรม
รอบที่ 0
รอบที่ 1
รอบที่ 2
0^2 = 0
1^2 = 1
2^2 = 4
3^2 = 9
4^2 = 16
total = 10
```

**หลักการออกแบบที่ดี**: แม้ C++ จะอนุญาตให้ประกาศตัวแปรได้ทุกที่ ก็ไม่ได้แปลว่าควรประกาศ
ตัวแปรทั้งหมดไว้ต้นฟังก์ชันเหมือนสมัยเขียน C แบบเก่า **แนวทางที่ดีที่สุดคือประกาศตัวแปรให้ใกล้
จุดที่ใช้งานจริงที่สุดเท่าที่จะทำได้** เพราะทำให้ scope ของตัวแปรแคบลง อ่านโค้ดง่ายขึ้น (ไม่ต้อง
เลื่อนขึ้นไปดูว่าตัวแปรนี้ประกาศเป็นชนิดอะไรตอนไหน) และลดโอกาสเผลอใช้ตัวแปรที่ยังไม่ได้กำหนดค่า
เริ่มต้น

### ความแตกต่างที่ 2: `bool` เป็น built-in type ในตัวภาษา

ทบทวนจาก Part 2: ภาษา C **ดั้งเดิมไม่มี `bool`** เลย เราใช้ `int` แทน (0 = false, ไม่ใช่ 0 =
true) จนกระทั่ง C99 เพิ่ม `_Bool` และ `<stdbool.h>` มาให้ `bool` เป็นแค่ macro ที่แทน `_Bool`
เท่านั้น (ทบทวนจาก Part 40 ที่ใช้ `#include <stdbool.h>` ใน `kv_store.h`)

ใน C++ **`bool` เป็น keyword และชนิดข้อมูลพื้นฐานในตัวภาษาโดยตรง** ไม่ต้อง include อะไรเพิ่ม
เลย:

```cpp
#include <iostream>

int main() {
    bool is_ready = true;
    bool has_error = false;

    std::cout << "is_ready = " << is_ready << '\n';
    std::cout << "has_error = " << has_error << '\n';
    std::cout << std::boolalpha;
    std::cout << "is_ready (boolalpha) = " << is_ready << '\n';

    std::cout << "sizeof(bool) = " << sizeof(bool) << " byte\n";

    return 0;
}
```

```
is_ready = 1
has_error = 0
is_ready (boolalpha) = true
sizeof(bool) = 1 byte
```

จุดที่น่าสังเกต: ค่าเริ่มต้นเมื่อพิมพ์ `bool` ผ่าน `std::cout` จะได้ `1`/`0` ไม่ใช่ `true`/`false`
ถ้าต้องการให้พิมพ์เป็นคำว่า `true`/`false` ต้องสั่ง `std::cout << std::boolalpha;` ก่อน (ตัว
`std::boolalpha` เป็น **stream manipulator** ตัวหนึ่ง — จะเจาะลึกเรื่อง manipulator เพิ่มเติม
ใน Part 42 และ Part 65)

### ความแตกต่างที่ 3: ความหมายของ `main()` เปลี่ยนไป

หัวข้อ 41.4 แอบพูดถึงประเด็นนี้ไปแล้ว มาขยายความให้ชัดเจน:

| รูปแบบ | ความหมายใน C | ความหมายใน C++ |
|---|---|---|
| `main()` | ไม่ระบุพารามิเตอร์ (ยอมรับอะไรก็ได้แบบไม่ตรวจสอบ) | ไม่รับพารามิเตอร์ใดๆ เลย (เหมือน `main(void)`) |
| `main(void)` | ไม่รับพารามิเตอร์ใดๆ เลย | ไม่รับพารามิเตอร์ใดๆ เลย (เหมือนกัน ใช้ได้ทั้งคู่) |

พูดง่ายๆ คือ **ใน C++ วงเล็บว่างกับ `void` มีความหมายเหมือนกันเป๊ะ** ไม่มีความแตกต่างแบบที่ C
มี (ทบทวน Common Pitfall ข้อ 3 ของ Part 1) เพราะ C++ ไม่มีแนวคิดเรื่อง "ฟังก์ชันที่ไม่ระบุ
พารามิเตอร์" อยู่เลยตั้งแต่ต้น — ทุกฟังก์ชันใน C++ ต้องประกาศพารามิเตอร์ให้ชัดเจนเสมอ (จะอธิบาย
เพิ่มเติมเรื่อง function signature ใน Part 44) หลักสูตรนี้จะใช้ `int main()` (วงเล็บว่าง) เป็น
รูปแบบมาตรฐานตลอด Module D เป็นต้นไป ตามธรรมเนียมที่นิยมที่สุดในโค้ด C++ สมัยใหม่

## 41.6 ความแตกต่างสำคัญ ตอนที่ 2: การตรวจสอบชนิดข้อมูลที่เข้มงวดกว่า (Step 326)

### ความแตกต่างที่ 4: C++ ไม่ยอมให้แปลง `void*` เป็นชนิดอื่นแบบ implicit

ทบทวน Part 11: ใน C เราเรียก `malloc()` แล้วเก็บผลลัพธ์ใส่ `int *` ได้ตรงๆ โดยไม่ต้อง cast
เพราะ C ยอมให้แปลง `void*` เป็น pointer ชนิดใดก็ได้แบบอัตโนมัติ (implicit conversion) ลองคอมไพล์
โค้ดแบบเดียวกันด้วย `g++`:

```cpp
#include <cstdlib>

int main() {
    int *arr = std::malloc(5 * sizeof(int));  // ผิด: ไม่ cast จาก void* เป็น int*
    (void)arr;
    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 bad_cast.cpp -o bad_cast
```

```
bad_cast.cpp: In function 'int main()':
bad_cast.cpp:4:27: error: invalid conversion from 'void*' to 'int*' [-fpermissive]
    4 |     int *arr = std::malloc(5 * sizeof(int));
      |                ~~~~~~~~~~~^~~~~~~~~~~~~~~~~
      |                           |
      |                           void*
```

**Error ไม่ใช่ Warning** — C++ ถือว่านี่เป็นข้อผิดพลาดร้ายแรงที่คอมไพล์ผ่านไม่ได้เลย ต้องแก้ด้วย
การ cast อย่างชัดเจนโดยใช้ `static_cast<T>()` (รูปแบบการ cast แบบ C++ ที่ปลอดภัยกว่า `(T)` แบบ
C-style cast มาก — จะเจาะลึกเรื่อง cast ทั้ง 4 แบบของ C++ ใน Part 54 และ Module F):

```cpp
#include <cstdlib>
#include <iostream>

int main() {
    // ใน C++ malloc คืน void* และต้อง cast เป็น int* อย่างชัดเจนเสมอ (ต่างจาก C ที่ implicit ได้)
    int *arr = static_cast<int *>(std::malloc(5 * sizeof(int)));
    if (arr == nullptr) {
        std::cerr << "จองหน่วยความจำไม่สำเร็จ\n";
        return 1;
    }

    for (int i = 0; i < 5; i++) {
        arr[i] = i * 10;
    }
    for (int i = 0; i < 5; i++) {
        std::cout << arr[i] << ' ';
    }
    std::cout << '\n';

    std::free(arr);
    return 0;
}
```

```
0 10 20 30 40
```

สังเกตด้วยว่าใช้ `nullptr` แทน `NULL` — `nullptr` เป็น keyword ของ C++11 ที่ type-safe กว่า
`NULL` มาก (ปัญหาของ `NULL` และเหตุผลที่ C++ ต้องมี `nullptr` จะอธิบายเจาะลึกใน Part 69) และ
ใช้ `<cstdlib>`/`<iostream>` (มี `c` นำหน้าและไม่มี `.h`) แทน `<stdlib.h>` — นี่คือรูปแบบมาตรฐาน
ที่ C++ ใช้เรียก C standard library header เข้ามาในเนมสเปซ `std::` (จะอธิบายเรื่อง namespace
เต็มรูปแบบใน Part 42)

> **ทำไม C++ เข้มงวดเรื่องนี้**: การแปลง `void*` แบบ implicit เป็นแหล่งบั๊กที่พบบ่อยมากในภาษา C
> — ลองนึกภาพเผลอเก็บผลลัพธ์ของ `malloc()` ผิดชนิด (เช่นตั้งใจจะได้ `int*` แต่ตัวแปรรับผลลัพธ์
> ดันประกาศเป็น `double*`) คอมไพเลอร์ C จะไม่เตือนอะไรเลยเพราะ implicit conversion ยอมให้ผ่าน
> ได้เสมอ ทำให้เกิดบั๊กที่ตรวจจับยากมาก C++ เลือกปิดช่องโหว่นี้โดยบังคับให้ผู้เขียนโค้ด "ยืนยัน
> ด้วยตัวเอง" ทุกครั้งที่แปลงชนิดข้อมูลแบบไม่ปลอดภัย

### ความแตกต่างที่ 5: ไม่มี "Implicit int" อีกต่อไป

ภาษา C แบบเก่ามาก (K&R C) เคยยอมให้เขียนฟังก์ชันโดยไม่ระบุชนิดคืนค่าได้ (คอมไพเลอร์จะสมมติว่า
เป็น `int` ให้อัตโนมัติ เรียกว่า "implicit int") มาตรฐาน C สมัยใหม่เลิกอนุญาตพฤติกรรมนี้ไปนานแล้ว
แต่คอมไพเลอร์ C บางตัวยังยอมให้ผ่านแบบมี Warning เป็นการประนีประนอม ส่วน C++ **ปิดประตูเรื่องนี้
เด็ดขาดตั้งแต่ต้น** กลายเป็น Error ทันที ไม่ใช่แค่ Warning:

```cpp
count() {   /* ผิด: C++ ไม่มี "implicit int" ต้องระบุชนิดคืนค่าเสมอ */
    return 5;
}

int main() {
    return count();
}
```

```
error: ISO C++ forbids declaration of 'count' with no type [-fpermissive]
```

### เพิ่มเติม: struct ไม่ต้องพึ่ง `typedef` อีกต่อไป

ทบทวน Part 10: ใน C เวลาประกาศตัวแปรจาก struct ต้องเขียน `struct Point p;` เสมอ (หรือใช้
`typedef struct Point Point;` เพื่อลัดคำว่า `struct` ทิ้งไป) ใน C++ ชื่อ struct (และ class)
กลายเป็นชื่อชนิดข้อมูล (type name) ได้ทันทีโดยไม่ต้อง `typedef` เลย:

```cpp
#include <iostream>

struct Point {
    int x;
    int y;
};

int main() {
    Point p1{1, 2};        // ไม่ต้องเขียน "struct Point" ซ้ำแบบใน C
    struct Point p2{3, 4}; // แบบเดิมของ C ก็ยังใช้ได้ ไม่ผิด แต่ไม่จำเป็นอีกต่อไป

    std::cout << "p1 = (" << p1.x << ", " << p1.y << ")\n";
    std::cout << "p2 = (" << p2.x << ", " << p2.y << ")\n";
    return 0;
}
```

```
p1 = (1, 2)
p2 = (3, 4)
```

รายละเอียดเรื่อง `struct` เทียบกับ `class` ใน C++ (ต่างกันแค่ default access specifier) จะ
อธิบายเต็มรูปแบบใน Part 47

### เพิ่มเติม: keyword ใหม่ที่ C++ สงวนไว้

C++ เพิ่ม keyword ใหม่หลายสิบตัวที่ C ไม่มี (เพราะต้องรองรับฟีเจอร์ใหม่อย่าง class, template,
exception) ที่พบบ่อยและสำคัญที่สุดคือ: `class`, `new`, `delete`, `template`, `public`,
`private`, `protected`, `virtual`, `try`, `catch`, `throw`, `namespace`, `bool`, `true`,
`false`, `this` — ถ้าเผลอเอาชื่อเหล่านี้ไปตั้งเป็นชื่อตัวแปรในโค้ด C เดิม เมื่อคอมไพล์ด้วย C++
จะ Error ทันที:

```c
#include <stdio.h>

int main(void) {
    int class = 5;   /* ผิด: class เป็น keyword สงวนไว้ใน C++ ใช้เป็นชื่อตัวแปรไม่ได้ */
    printf("%d\n", class);
    return 0;
}
```

```
error: expected primary-expression before 'int'
error: expected primary-expression before 'class'
```

โค้ด C ตัวนี้ **คอมไพล์ผ่านสบายๆ ด้วย gcc** (เพราะ `class` ไม่ใช่ keyword ของ C) แต่พัง
ทันทีเมื่อคอมไพล์ด้วย `g++` — นี่คือประเด็นสำคัญที่จะพูดถึงต่อในหัวข้อ 41.8

## 41.7 `new`/`delete` แทน `malloc`/`free` (Step 327)

C++ มีตัวดำเนินการ `new` และ `delete` สำหรับจัดการหน่วยความจำแบบไดนามิกแทนที่
`malloc`/`free` ของ C แม้ `malloc`/`free` จะยังใช้งานได้ปกติใน C++ (ดังที่เห็นในหัวข้อ 41.6)
แต่ **`new`/`delete` คือวิธีมาตรฐานที่โค้ด C++ ควรใช้** ด้วยเหตุผลหลายข้อ

### ตัวอย่างการใช้งานพื้นฐาน

```cpp
#include <iostream>

struct Point {
    int x;
    int y;
};

int main() {
    // new แบบตัวแปรเดี่ยว
    int *p = new int;
    *p = 42;
    std::cout << "*p = " << *p << '\n';
    delete p;

    // new แบบมีค่าเริ่มต้น (initialize ทันที)
    int *q = new int(99);
    std::cout << "*q = " << *q << '\n';
    delete q;

    // new[] สำหรับ array แบบไดนามิก
    int n = 5;
    int *arr = new int[n];
    for (int i = 0; i < n; i++) {
        arr[i] = i * i;
    }
    for (int i = 0; i < n; i++) {
        std::cout << arr[i] << ' ';
    }
    std::cout << '\n';
    delete[] arr;  // ต้องใช้ delete[] คู่กับ new[] เสมอ

    // new กับ struct/class
    Point *pt = new Point{3, 4};
    std::cout << "pt->x = " << pt->x << ", pt->y = " << pt->y << '\n';
    delete pt;

    return 0;
}
```

```
*p = 42
*q = 99
0 1 4 9 16
pt->x = 3, pt->y = 4
```

### ตารางเปรียบเทียบ `malloc`/`free` กับ `new`/`delete`

| ประเด็น | `malloc`/`free` (C) | `new`/`delete` (C++) |
|---|---|---|
| ต้องระบุขนาดเป็นไบต์เอง | ใช่ (`malloc(n * sizeof(int))`) | ไม่ต้อง — คอมไพเลอร์คำนวณขนาดจากชนิดข้อมูลให้ |
| ต้อง cast ผลลัพธ์ | ต้อง cast ใน C++ (หัวข้อ 41.6) ไม่ต้องใน C | ไม่ต้อง cast เลย คืน pointer ชนิดที่ถูกต้องเสมอ |
| ใส่ค่าเริ่มต้นพร้อมจอง | ทำไม่ได้ในคำสั่งเดียว ต้องจองแล้วกำหนดค่าแยก | ทำได้ในคำสั่งเดียว เช่น `new int(99)` |
| เรียก constructor ของ class | ไม่เรียก (C ไม่มี constructor) | เรียกอัตโนมัติเสมอ (สำคัญมากเมื่อเริ่มเขียน class ใน Part 46) |
| เมื่อจองไม่สำเร็จ | คืน `NULL` | โยน exception `std::bad_alloc` (ค่าเริ่มต้น) |
| จองแบบ array | `malloc(n * sizeof(T))` | `new T[n]` |
| คืนหน่วยความจำแบบ array | `free(ptr)` ตัวเดียวใช้ได้ทุกกรณี | ต้องใช้ `delete[]` คู่กับ `new[]` เท่านั้น (ห้ามใช้ `delete` เฉยๆ) |
| ผสมกันได้ไหม | — | **ห้ามผสม**: จองด้วย `malloc` ต้องคืนด้วย `free`, จองด้วย `new` ต้องคืนด้วย `delete` เท่านั้น |

### ทำไม `new` ปลอดภัยกว่า

จุดที่สำคัญที่สุดในตารางคือแถว "เรียก constructor" — เมื่อเริ่มเขียน class ใน Part 45 เป็นต้นไป
`new` จะกลายเป็นเครื่องมือที่ขาดไม่ได้ เพราะมันไม่ได้แค่ "จองหน่วยความจำ" เหมือน `malloc` แต่ยัง
**เรียก constructor ของ object นั้นให้อัตโนมัติ** เพื่อสร้าง object ที่อยู่ในสถานะที่ถูกต้อง
สมบูรณ์ทันทีที่จองเสร็จ (`malloc` ทำได้แค่จองพื้นที่ว่างเปล่าเท่านั้น ไม่รู้จักแนวคิดเรื่อง
constructor เลย เพราะเป็นฟังก์ชันของ C ล้วนๆ)

ในทางกลับกัน `delete` ก็จะเรียก **destructor** ให้อัตโนมัติก่อนคืนหน่วยความจำ (จะอธิบายเต็ม
รูปแบบใน Part 46) นี่คือรากฐานสำคัญของแนวคิด RAII ที่กล่าวถึงในหัวข้อ 41.2

> **กฎทองของหัวข้อนี้**: ในโค้ด C++ ตั้งแต่ Part นี้เป็นต้นไป หลักสูตรจะใช้ `new`/`delete` เป็น
> หลักเสมอ ยกเว้นกรณีพิเศษที่ต้องทำงานร่วมกับ C library เดิมโดยตรง (เช่นเรียก C library ที่คืน
> ค่าจาก `malloc` มาให้) และ **ห้ามผสม `malloc` กับ `delete` หรือ `new` กับ `free`** เด็ดขาด
> เพราะพฤติกรรมที่เกิดขึ้นเป็น Undefined Behavior ทันที (ทบทวนแนวคิด UB จาก Part 1 และ Part 38)

## 41.8 คอมไพล์โค้ด C เดิมด้วย g++ และภาพรวมมาตรฐาน C++ (Step 328)

### ทดลอง: เอาโค้ด C จาก Module A มาคอมไพล์ด้วย g++ ตรงๆ

ลองเอาโปรแกรมคำนวณค่าเฉลี่ยแบบง่ายๆ สไตล์ Module A มาคอมไพล์ด้วย `g++` โดยไม่แก้ไขอะไรเลย
(แค่เปลี่ยนนามสกุลไฟล์เป็น `.cpp`):

```cpp
/* averaging.c ตัวเดิมจาก Module A แต่คอมไพล์ด้วย g++ ตรงๆ (นามสกุล .cpp) */
#include <stdio.h>

int main(void) {
    int numbers[5] = {10, 20, 30, 40, 50};
    int sum = 0;

    for (int i = 0; i < 5; i++) {
        sum += numbers[i];
    }

    double average = (double)sum / 5;
    printf("ผลรวม = %d, ค่าเฉลี่ย = %.2f\n", sum, average);

    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 averaging.cpp -o averaging
./averaging
```

```
ผลรวม = 150, ค่าเฉลี่ย = 30.00
```

**คอมไพล์ผ่านโดยไม่มี Warning แม้แต่บรรทัดเดียว!** นี่คือสิ่งสำคัญที่ต้องเข้าใจ: **C++ ถูก
ออกแบบให้เป็น superset ของ C เกือบทั้งหมด** (ไม่ใช่ 100% เป๊ะ แต่ใกล้เคียงมาก) โค้ด C ที่เขียน
ถูกต้องตามมาตรฐานส่วนใหญ่จะคอมไพล์ผ่านด้วย C++ compiler ได้เลยโดยแทบไม่ต้องแก้ไขอะไร แม้แต่
`<stdio.h>` แบบเก่าก็ยังใช้ `printf` ได้ปกติ (แม้ว่าในโค้ด C++ สมัยใหม่จะนิยมใช้ `<iostream>`
กับ `std::cout` มากกว่าตามที่เห็นในหัวข้อ 41.4 ก็ตาม)

### แต่ก็ไม่ใช่ 100% เหมือนกันเป๊ะ — จุดที่ต้องระวัง

จากหัวข้อ 41.6 เราเห็นแล้วว่า `int class = 5;` และการแปลง `void*` แบบ implicit ทำให้โค้ด C
เดิม**คอมไพล์ไม่ผ่านเลย**เมื่อใช้ `g++` มีอีกตัวอย่างที่ผลลัพธ์ **ต่างกันแบบเงียบๆ โดยไม่มี Error
หรือ Warning เตือนเลย** ซึ่งอันตรายกว่าเดิมนะ: ขนาดของ character literal

```cpp
/* char_size.cpp — คอมไพล์ด้วย g++ */
#include <cstdio>

int main(void) {
    printf("sizeof('a') = %zu\n", sizeof('a'));
    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 char_size.cpp -o char_size_cpp
./char_size_cpp
```

```
sizeof('a') = 1
```

เทียบกับโค้ดเดียวกันเป๊ะ (เปลี่ยนแค่นามสกุลไฟล์) คอมไพล์ด้วย `gcc`:

```bash
gcc -Wall -Wextra -Wpedantic -std=c17 char_size.c -o char_size_c
./char_size_c
```

```
sizeof('a') = 4
```

**ผลลัพธ์ต่างกัน!** เพราะใน C ตัว character literal อย่าง `'a'` มีชนิดเป็น `int` (4 ไบต์บน
ระบบทั่วไป) ด้วยเหตุผลทางประวัติศาสตร์ที่สืบทอดมาจาก C ยุคแรกเริ่ม ส่วนใน C++ `'a'` มีชนิดเป็น
`char` (1 ไบต์) ตรงตามที่ควรจะเป็นโดยสัญชาตญาณ — ความต่างเล็กๆ แบบนี้ไม่ค่อยส่งผลกระทบในโค้ด
ทั่วไป แต่ถ้ามีโค้ดที่พึ่งพาค่า `sizeof` ของ character literal โดยเฉพาะ (พบได้ในโค้ดระดับ
Low-level บางแบบ) ผลลัพธ์จะไม่เหมือนเดิมทันทีที่ย้ายจาก C ไป C++

> **บทเรียนสำคัญของหัวข้อนี้**: การที่โค้ดคอมไพล์ผ่านทั้งใน `gcc` และ `g++` ไม่ได้แปลว่าพฤติกรรม
> จะเหมือนกันเป๊ะเสมอไป C++ ไม่ใช่ "C ที่มีฟีเจอร์เพิ่มเข้ามาอย่างเดียว" แต่เป็นภาษาที่มีกฎของ
> ตัวเองในหลายจุด แม้จะดูคล้าย C มากก็ตาม เมื่อย้ายโค้ด C เดิมมาเป็น C++ ควรอ่านผ่านทั้งไฟล์และ
> ทดสอบผลลัพธ์อีกครั้งเสมอ ไม่ควรสมมติว่า "คอมไพล์ผ่าน = ทำงานเหมือนเดิมทุกประการ"

### ภาพรวมมาตรฐานของ C++ (จะเจาะลึกใน Module F)

เช่นเดียวกับ C ที่มีมาตรฐาน C89 → C99 → C11 → C17 → C23 (ทบทวนตารางจาก Part 1) C++ ก็มีการ
พัฒนามาตรฐานผ่าน ISO อย่างต่อเนื่อง:

| มาตรฐาน | ปีที่ออก | จุดเด่นสำคัญ |
|---|---|---|
| C++98 | 1998 | มาตรฐานทางการฉบับแรก กำหนดรูปแบบของ STL, Template, Exception ให้เป็นทางการ |
| C++03 | 2003 | แก้ไขข้อบกพร่องเล็กน้อยของ C++98 (ไม่มีฟีเจอร์ใหม่สำคัญ) |
| C++11 | 2011 | การปฏิวัติครั้งใหญ่ที่สุดของภาษา: `auto`, lambda, `nullptr`, range-based for, move semantics, smart pointer (จะเรียนเต็มรูปแบบใน Part 69–70) |
| C++14 | 2014 | ปรับปรุง C++11 ให้ใช้งานง่ายขึ้น (generic lambda, relaxed constexpr) |
| C++17 | 2017 | `std::optional`, `std::variant`, structured bindings, `if constexpr` — **มาตรฐานหลักของหลักสูตรนี้ในช่วง Module D–E** |
| C++20 | 2020 | Concepts, Ranges, Coroutines, Modules — การเปลี่ยนแปลงครั้งใหญ่อีกครั้ง (Part 73–76) |
| C++23 | 2023/2024 | `std::expected`, ปรับปรุง Ranges และ Modules เพิ่มเติม (Part 77) |

หลักสูตรนี้จะใช้ **C++17** เป็นมาตรฐานหลักตลอด Module D และ E เพราะเป็นจุดที่สมดุลที่สุด
ระหว่างฟีเจอร์ที่ทันสมัยเพียงพอกับความเสถียรของ compiler ทุกตัวในตลาด เมื่อเข้าสู่ **Module F**
(Part 69 เป็นต้นไป) เราจะย้อนกลับไปเรียนรู้ C++11 อย่างละเอียด แล้วไล่เรียงมาจนถึง C++23 ทีละ
มาตรฐาน เพื่อให้เข้าใจว่าแต่ละฟีเจอร์ถูกเพิ่มเข้ามาแก้ปัญหาอะไร และทำไมถึงเป็นตัวเปลี่ยนเกม
ของวงการ C++ สมัยใหม่

## ข้อผิดพลาดที่พบบ่อย (Common Pitfalls)

1. **สับสนคิดว่า C++ เป็น C ที่มีแค่ class เพิ่มเข้ามา** — ในความเป็นจริง C++ มีกฎของตัวเองที่
   เข้มงวดกว่า C ในหลายจุด (การ cast, implicit int, keyword ใหม่) การนำโค้ด C เดิมมาใช้ควรอ่าน
   ผ่านทั้งไฟล์เสมอ ไม่ควรสมมติว่าคอมไพล์ผ่านแล้วจะทำงานเหมือนเดิมทุกประการ (ทบทวนตัวอย่าง
   `sizeof('a')` จากหัวข้อ 41.8)
2. **ลืม cast ผลลัพธ์จาก `malloc()`** — โค้ด C ที่ก็อปมาใช้ตรงๆ จะ Error ทันทีเมื่อคอมไพล์ด้วย
   `g++` เพราะ C++ ไม่ยอมให้แปลง `void*` แบบ implicit แก้ด้วย `static_cast<T*>()` เสมอ
3. **ผสม `malloc`/`free` กับ `new`/`delete`** — เช่นจองด้วย `new` แต่คืนด้วย `free()` หรือจอง
   ด้วย `malloc()` แต่คืนด้วย `delete` พฤติกรรมที่เกิดขึ้นเป็น Undefined Behavior ทันที เพราะ
   ทั้งคู่อาจใช้กลไกจัดการหน่วยความจำภายในที่ต่างกัน (`new` อาจเรียก constructor/destructor ที่
   `malloc`/`free` ไม่รู้จักเลย)
4. **ใช้ `new[]` แต่คืนด้วย `delete` เฉยๆ (ไม่ใช่ `delete[]`)** — ต้องจับคู่ `new[]` กับ
   `delete[]` เท่านั้น การใช้ `delete` ตัวเดียวกับ pointer ที่ได้จาก `new[]` เป็น Undefined
   Behavior แม้โปรแกรมอาจดูเหมือนทำงานได้ปกติในบางกรณีก็ตาม (จะยิ่งอันตรายมากขึ้นเมื่อเป็น
   array ของ object ที่มี destructor ใน Part 46)
5. **เอาชื่อ keyword ใหม่ของ C++ ไปตั้งเป็นชื่อตัวแปรในโค้ด C เดิม** — เช่น `class`, `new`,
   `delete`, `template`, `this` โค้ด C ที่ใช้ชื่อเหล่านี้เป็นตัวแปรจะคอมไพล์ผ่านปกติด้วย `gcc`
   แต่ Error ทันทีด้วย `g++`
6. **เข้าใจผิดว่า `main()` ใน C++ ยอมรับพารามิเตอร์แบบไม่ตรวจสอบเหมือน C** — ใน C++ `main()`
   วงเล็บว่างหมายถึง "ไม่รับพารามิเตอร์เลย" เหมือนกับ `main(void)` เป๊ะ ต่างจาก C ที่ทั้งสอง
   รูปแบบมีความหมายต่างกัน

### แนวทางเฉลยข้อ 1

```cpp
#include <iostream>

int main() {
    double celsius_values[4] = {0.0, 25.0, 37.5, 100.0};

    for (int i = 0; i < 4; i++) {
        double celsius = celsius_values[i];               // ประกาศตัวแปรกลาง loop ได้ทันที
        double fahrenheit = celsius * 9.0 / 5.0 + 32.0;
        bool is_boiling = (celsius >= 100.0);              // bool เป็น built-in type ของ C++

        std::cout << celsius << " C = " << fahrenheit << " F";
        if (is_boiling) {
            std::cout << " (จุดเดือดของน้ำ)";
        }
        std::cout << '\n';
    }

    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 temp_convert.cpp -o temp_convert

```

อยู่**ข้างในลูป** ไม่ใช่ต้นฟังก์ชันแบบสไตล์ C89 และ `is_boiling` เป็น `bool` แท้ๆ ที่ใช้ใน

### แนวทางเฉลยข้อ 3

```cpp
#include <iostream>

int main() {
    int n = 6;
    int *scores = new int[n]{88, 92, 75, 60, 99, 84};  // จองและใส่ค่าเริ่มต้นในคำสั่งเดียว

    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum += scores[i];
    }
    double average = static_cast<double>(sum) / n;

    std::cout << "คะแนนทั้งหมด: ";
    for (int i = 0; i < n; i++) {
        std::cout << scores[i] << ' ';
    }
    std::cout << "\nผลรวม = " << sum << "\n";
    std::cout << "ค่าเฉลี่ย = " << average << "\n";

    delete[] scores;  // ต้องคู่กับ new[] เสมอ มิฉะนั้นเป็น Undefined Behavior
    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 exam_stats.cpp -o exam_stats
./exam_stats
```

```
คะแนนทั้งหมด: 88 92 75 60 99 84
ผลรวม = 498
ค่าเฉลี่ย = 83
```

จุดสำคัญของเฉลยนี้: `new int[n]{...}` แสดงให้เห็นว่า C++ จองหน่วยความจำแบบ array **พร้อมใส่
ค่าเริ่มต้นได้ในคำสั่งเดียว** ซึ่งเป็นสิ่งที่ `malloc()` ทำไม่ได้เลย (`malloc` จองพื้นที่ว่างเปล่า
เท่านั้น ต้องวนลูปใส่ค่าทีหลังเสมอ) และการหาร `sum / n` ถูก cast เป็น `double` ก่อนด้วย
`static_cast<double>(sum)` เพื่อให้ได้ผลลัพธ์เป็นทศนิยม ตรงตามหลักการ cast แบบชัดเจนของ C++
ที่เรียนในหัวข้อ 41.6 — สังเกตว่า `delete[]` ถูกเรียกครั้งเดียวตอนจบโปรแกรม จับคู่กับ `new[]`
ที่จองไว้ตอนต้นอย่างถูกต้อง
