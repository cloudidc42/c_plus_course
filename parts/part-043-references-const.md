## เป้าหมายการเรียนรู้ (Learning Objectives)

หลังจบ Part นี้ ผู้เรียนจะสามารถ:

1. อธิบายได้ว่า **Reference** (`&`) คืออะไร และประกาศ/ใช้งาน reference ได้อย่างถูกต้อง
2. เปรียบเทียบ Reference กับ Pointer ได้อย่างละเอียด ทั้งจุดที่เหมือนกัน (ระดับ machine code)
   และจุดที่ต่างกัน (กฎทางภาษาที่คอมไพเลอร์บังคับ)
3. ใช้ Reference เป็นพารามิเตอร์ของฟังก์ชัน (Pass by Reference) เพื่อแก้ปัญหาการ copy ข้อมูล
   จำนวนมากโดยไม่จำเป็นที่เกิดจาก Pass by Value
4. ใช้ `const` ได้อย่างครบถ้วนและถูกต้อง (const variable, pointer-to-const, const-pointer,
   const reference parameter) ตามหลักการที่เรียกว่า **const correctness**
5. อธิบายได้ว่าทำไม **const reference parameter** เป็นวิธีที่ปลอดภัยและมีประสิทธิภาพที่สุดใน
   การรับพารามิเตอร์ที่มีขนาดใหญ่ (เช่น `std::string`, `std::vector`) เข้าฟังก์ชัน
6. ตัดสินใจได้ว่าเมื่อไหร่ควรใช้ pointer เมื่อไหร่ควรใช้ reference ในการออกแบบฟังก์ชันแต่ละแบบ
7. เขียนฟังก์ชันที่คืนค่าเป็น reference ได้อย่างปลอดภัย และอธิบายอันตรายของการคืน reference
   ไปยัง local variable ได้อย่างชัดเจน พร้อมยกตัวอย่างจริงที่คอมไพล์ได้แต่เป็น Undefined
   Behavior

## 43.1 Reference คืออะไร (Step 337)

### แนวคิดหลัก: "อีกชื่อหนึ่ง" ของตัวแปรเดิม

**Reference** คือฟีเจอร์ใหม่ของ C++ ที่ C ไม่มี มันคือการสร้าง **ชื่อเล่น (alias)** ให้กับ
ตัวแปรที่มีอยู่แล้ว — ไม่ใช่ตัวแปรใหม่ ไม่ใช่สำเนา แต่เป็น **อีกชื่อหนึ่งของตัวแปรตัวเดียวกันเป๊ะ**
ประกาศด้วยเครื่องหมาย `&` ต่อท้ายชนิดข้อมูล:

```cpp
#include <iostream>

int main() {
    int score = 80;
    int &score_ref = score;  // score_ref คือ "อีกชื่อหนึ่ง" ของ score ตัวเดียวกัน ไม่ใช่ตัวแปรใหม่

    std::cout << "score = " << score << ", score_ref = " << score_ref << '\n';

    score_ref = 95;  // แก้ผ่าน reference ก็เท่ากับแก้ score โดยตรง
    std::cout << "หลังแก้ score_ref: score = " << score << '\n';

    score = 60;  // แก้ผ่านตัวแปรเดิม ก็สะท้อนไปที่ reference ด้วย
    std::cout << "หลังแก้ score: score_ref = " << score_ref << '\n';

    std::cout << "&score = " << &score << ", &score_ref = " << &score_ref << '\n';

    return 0;
}
```

```
score = 80, score_ref = 80
หลังแก้ score_ref: score = 95
หลังแก้ score: score_ref = 60
&score = 0x7fffd8af37bc, &score_ref = 0x7fffd8af37bc
```

จุดที่สำคัญที่สุดในตัวอย่างนี้คือบรรทัดสุดท้าย: **`&score` กับ `&score_ref` เป็นแอดเดรสเดียวกัน
เป๊ะ** พิสูจน์ว่า `score` และ `score_ref` ไม่ใช่ตัวแปรสองตัวที่บังเอิญมีค่าเท่ากัน แต่เป็น
**ตัวแปรตัวเดียวกันที่มีสองชื่อ**

### กฎเหล็กข้อที่ 1: Reference ต้อง Initialize ทันทีตอนประกาศ

```cpp
int main() {
    int &r;  // ผิด: reference ต้อง initialize ทันทีตอนประกาศ ไม่มีข้อยกเว้น
    return 0;
}
```

```
error: 'r' declared as reference but not initialized
```

ต่างจาก pointer ที่ประกาศไว้ก่อนแล้วค่อยกำหนดค่าทีหลังได้ (`int *p; ... p = &x;`) **reference
ต้องรู้ทันทีตั้งแต่บรรทัดที่ประกาศว่าจะเป็น "ชื่อเล่น" ของตัวแปรตัวไหน** ไม่มีสถานะ "ยังไม่ผูก
กับใคร" อยู่เลย เหตุผลเชิงแนวคิด: reference ไม่ใช่ "กล่องที่เก็บแอดเดรส" แบบ pointer แต่คือ
"ป้ายชื่ออีกป้ายหนึ่ง" ที่ติดอยู่กับตัวแปรที่มีอยู่แล้วเท่านั้น — ป้ายชื่อที่ยังไม่ได้ติดอะไรเลย
จึงไม่มีความหมาย

### กฎเหล็กข้อที่ 2: ไม่มี Null Reference

เพราะ reference ต้องผูกกับตัวแปรจริงตั้งแต่แรกเสมอ (กฎข้อที่ 1) จึง **ไม่มีทางสร้าง reference
ที่ "ไม่ได้ชี้อะไรเลย" ได้ตามกฎของภาษา** ต่างจาก pointer ที่ตั้งเป็น `nullptr` ได้ตลอดเวลา
นี่คือข้อดีสำคัญของ reference: **ฟังก์ชันที่รับ parameter เป็น reference ไม่ต้องตรวจสอบ
`nullptr` เลย** เพราะเป็นไปไม่ได้ตามกฎภาษาที่ reference จะไม่ผูกกับตัวแปรจริง (ทบทวนปัญหา
Null Pointer Dereference จาก Part 9 ที่ต้องคอยเช็ค `if (p != NULL)` อยู่ตลอดเวลาใน C)

> หมายเหตุเชิงลึก (ข้ามได้สำหรับตอนนี้): ในทางเทคนิคสามารถ "แอบ" สร้างสถานการณ์ที่ reference
> ทำงานผิดพลาดคล้าย null ได้ผ่านการทำ Undefined Behavior โดยตรง (เช่น dereference null
> pointer แล้วผูกเป็น reference) แต่นั่นไม่ใช่การใช้งานปกติที่ภาษาอนุญาตให้ทำ และเป็นสิ่งที่ไม่
> ควรเขียนแม้แต่น้อย — สำหรับการใช้งานปกติทุกกรณี **reference ที่สร้างถูกต้องตามกฎจะไม่มีทางเป็น
> null ได้เลย**

### กฎเหล็กข้อที่ 3: Reference "Reseat" ไปผูกกับตัวแปรอื่นไม่ได้

```cpp
#include <iostream>

int main() {
    int a = 10;
    int b = 20;

    int &ref = a;   // ref ผูกกับ a
    ref = b;        // นี่ไม่ใช่การเปลี่ยนให้ ref ไปชี้ b! แต่เป็นการ "copy ค่าของ b ไปใส่ a"

    std::cout << "a = " << a << '\n';  // a กลายเป็น 20 เพราะ ref ยังคงเป็น a อยู่เสมอ
    std::cout << "b = " << b << '\n';
    std::cout << "ref = " << ref << '\n';

    return 0;
}
```

```
a = 20
b = 20
ref = 20
```

จุดที่มือใหม่สับสนบ่อยที่สุด: `ref = b;` **ไม่ได้แปลว่า "ให้ ref ไปผูกกับ b แทน"** แต่แปลว่า
"เอาค่าของ `b` ไป **assign** ใส่สิ่งที่ `ref` ผูกอยู่ (คือ `a`)" เพราะเมื่อ reference ผูกกับ
ตัวแปรใดแล้ว **มันจะผูกกับตัวแปรนั้นตลอดชีวิตของมัน ไม่มีทางเปลี่ยนไปผูกกับตัวแปรอื่นได้อีก**
(เรียกว่า reference "reseat ไม่ได้") นี่คือความต่างที่สำคัญที่สุดจาก pointer ซึ่งจะอธิบายต่อใน
หัวข้อถัดไป

## 43.2 Reference ต่างจาก Pointer อย่างไร (Step 338)

```cpp
#include <iostream>

int main() {
    int x = 100;

    // Pointer: ต้อง dereference ด้วย *, เช็ค null ได้, ชี้ใหม่ได้
    int *p = &x;
    std::cout << "*p = " << *p << '\n';
    int y = 200;
    p = &y;  // reseat ได้: ตอนนี้ p ชี้ y แทน
    std::cout << "*p (หลัง reseat) = " << *p << '\n';
    p = nullptr;  // pointer เป็น null ได้
    std::cout << "p is nullptr: " << (p == nullptr) << '\n';

    // Reference: ใช้ตรงๆ ไม่ต้อง dereference, ผูกติดตัวแปรเดียวตลอดชีวิต
    int &r = x;
    std::cout << "r = " << r << '\n';  // ไม่ต้องใช้ * เลย

    return 0;
}
```

```
*p = 100
*p (หลัง reseat) = 200
p is nullptr: 1
r = 100
```

### ตารางเปรียบเทียบสรุป

| ประเด็น | Pointer (`T*`) | Reference (`T&`) |
|---|---|---|
| ต้อง initialize ทันทีตอนประกาศไหม | ไม่ต้อง (ประกาศก่อน กำหนดค่าทีหลังได้) | **ต้อง** เสมอ |
| เป็น `nullptr`/null ได้ไหม | ได้ | **ไม่ได้** ตามกฎการใช้งานปกติ |
| Reseat ไปชี้ตัวแปรอื่นได้ไหม | ได้ตลอดเวลา (`p = &other;`) | **ไม่ได้** ผูกกับตัวแปรเดิมตลอดชีวิต |
| ต้อง dereference เพื่อเข้าถึงค่าไหม | ต้องใช้ `*p` | ไม่ต้อง ใช้ `r` ตรงๆ ได้เลย |
| ทำ Pointer Arithmetic ได้ไหม (`p++`, `p + 1`) | ได้ (ทบทวน Part 9) | **ไม่ได้** ไม่มีแนวคิดนี้เลย |
| ทำ array ของมันได้ไหม | ได้ (`int *arr[10]`) | **ไม่ได้** ไม่มี "array of reference" ในภาษา |
| ขนาดที่แท้จริงในหน่วยความจำ | มีขนาดจริง (ปกติ 8 ไบต์บนระบบ 64-bit) | ไม่มีขนาดที่นิยามชัดเจน (ทางปฏิบัติคอมไพเลอร์มักใช้กลไกคล้าย pointer ภายใน แต่ภาษาซ่อนรายละเอียดนี้ไว้ทั้งหมด) |
| เหมาะกับงานแบบไหน | โครงสร้างข้อมูล (linked list, tree), optional value ที่อาจไม่มี | พารามิเตอร์ฟังก์ชัน, ค่าที่ยืนยันแล้วว่ามีอยู่จริงเสมอ |

### เบื้องหลัง: Reference "เหมือน" Pointer ในระดับเครื่อง แต่ไม่ใช่สิ่งเดียวกันในระดับภาษา

ในทางปฏิบัติ คอมไพเลอร์ส่วนใหญ่ implement reference ด้วยกลไกที่คล้ายกับ pointer มากในระดับ
Assembly (เก็บแอดเดรสไว้เหมือนกัน) แต่นี่เป็นแค่ **รายละเอียดการ implement** ไม่ใช่ส่วนหนึ่งของ
มาตรฐานภาษา C++ สิ่งสำคัญที่ต้องจำคือ **C++ มองว่า reference เป็นแค่ "ชื่อเล่น" ของตัวแปร ไม่ใช่
"ตัวแปรที่เก็บแอดเดรส" แบบ pointer** — นี่คือเหตุผลที่ `sizeof` ของ reference จะให้ผลลัพธ์เป็น
ขนาดของ**ตัวแปรที่มันอ้างถึง** ไม่ใช่ขนาดของแอดเดรส (ต่างจาก `sizeof` ของ pointer ที่ให้ขนาด
ของแอดเดรสเสมอไม่ว่าจะชี้ชนิดข้อมูลอะไร) ลองพิสูจน์ด้วยโค้ดจริง:

```cpp
#include <iostream>

int main() {
    int x = 10;
    int *p = &x;
    int &r = x;

    std::cout << "sizeof(x) = " << sizeof(x) << '\n';
    std::cout << "sizeof(p) = " << sizeof(p) << '\n';
    std::cout << "sizeof(r) = " << sizeof(r) << '\n';

    double d = 3.14;
    double *pd = &d;
    double &rd = d;
    std::cout << "sizeof(pd) = " << sizeof(pd) << '\n';   // ขนาดของ pointer เท่าเดิมเสมอ (แอดเดรส)
    std::cout << "sizeof(rd) = " << sizeof(rd) << '\n';   // ขนาดของ double ที่ r อ้างถึง ไม่ใช่ขนาดแอดเดรส

    return 0;
}
```

```
sizeof(x) = 4
sizeof(p) = 8
sizeof(r) = 4
sizeof(pd) = 8
sizeof(rd) = 8
```

สังเกตว่า `sizeof(p)` และ `sizeof(pd)` เท่ากันเป๊ะที่ 8 ไบต์ (ขนาดแอดเดรสบนระบบ 64-bit) **ไม่ว่า
จะชี้ไปยัง `int` หรือ `double` ก็ตาม** เพราะ pointer เก็บแค่แอดเดรสเสมอ แต่ `sizeof(r)` ได้ 4
(เท่ากับ `sizeof(int)`) และ `sizeof(rd)` ได้ 8 (เท่ากับ `sizeof(double)`) — ยืนยันว่าในสายตา
ของภาษา C++ **reference ไม่มีขนาดหรือตัวตนเป็นของตัวเองเลย มันคือตัวแปรที่มันอ้างถึงนั่นเอง**

## 43.3 Reference เป็นพารามิเตอร์: Pass by Reference (Step 339)

### ทบทวนปัญหาของ Pass by Value

ทบทวน Part 6: ภาษา C มีแค่ **Pass by Value** เท่านั้น — เมื่อส่ง argument เข้าฟังก์ชัน จะมีการ
**copy ค่า** เข้าไปในพารามิเตอร์เสมอ ฟังก์ชันแก้ไขพารามิเตอร์ของตัวเองได้ แต่ไม่กระทบตัวแปร
ต้นฉบับที่ผู้เรียกส่งเข้ามาเลย ถ้าต้องการให้ฟังก์ชันแก้ไขตัวแปรต้นฉบับได้ ใน C ต้องส่ง **pointer**
เข้าไปแทน (ทบทวนฟังก์ชัน `swap` แบบ C ที่ต้องรับ `int *a, int *b`)

C++ เพิ่มความสามารถใหม่: **Pass by Reference** — ประกาศพารามิเตอร์เป็น reference (`T &param`)
ฟังก์ชันจะได้ "ชื่อเล่น" ของตัวแปรต้นฉบับโดยตรง ไม่มีการ copy เลย และแก้ไขพารามิเตอร์เท่ากับแก้
ตัวแปรต้นฉบับทันที **โดยไม่ต้องใช้ pointer หรือ `&`/`*` เลยแม้แต่นิดเดียวตอนเรียกใช้**

```cpp
#include <iostream>

void double_by_value(int x) {
    x = x * 2;  // แก้แค่สำเนา ไม่กระทบตัวแปรต้นฉบับเลย
}

void double_by_reference(int &x) {
    x = x * 2;  // แก้ตัวแปรต้นฉบับโดยตรงผ่าน reference
}

void swap_by_reference(int &a, int &b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int n = 5;
    double_by_value(n);
    std::cout << "หลัง double_by_value: n = " << n << '\n';

    double_by_reference(n);
    std::cout << "หลัง double_by_reference: n = " << n << '\n';

    int x = 1;
    int y = 2;
    swap_by_reference(x, y);
    std::cout << "หลัง swap: x = " << x << ", y = " << y << '\n';

    return 0;
}
```

```
หลัง double_by_value: n = 5
หลัง double_by_reference: n = 10
หลัง swap: x = 2, y = 1
```

เปรียบเทียบกับฟังก์ชัน `swap` แบบ C จาก Part 9 ที่ต้องเขียน `void swap(int *a, int *b)` แล้ว
เรียกด้วย `swap(&x, &y)` — โค้ด C++ ด้านบนเรียกง่ายกว่ามาก (`swap_by_reference(x, y)`) แต่ยังคง
ผลลัพธ์เดียวกันทุกประการ **นี่คือคำตอบเต็มรูปแบบของคำถามที่ค้างไว้จาก Part 42**: ตอนนี้เข้าใจ
แล้วว่าทำไม `std::cin >> a >> b` ไม่ต้องใช้ `&a`, `&b` เหมือน `scanf` — เพราะ `operator>>` ของ
`std::cin` internally รับพารามิเตอร์เป็น **reference** ไม่ใช่ pointer

### เมื่อไหร่ไม่ควรใช้ reference เป็นพารามิเตอร์เฉยๆ

Reference ธรรมดา (ไม่ใช่ `const`) แบบในตัวอย่างข้างต้นเหมาะกับกรณีที่ **ฟังก์ชันตั้งใจจะแก้ไข**
ค่าของ argument จริงๆ (เช่น `swap`, การอัปเดตค่า) แต่ถ้าฟังก์ชันแค่ต้องการ **อ่าน** ค่าเข้าไปใช้
โดยไม่ตั้งใจแก้ไขอะไรเลย การใช้ reference ธรรมดาเปิดช่องให้เกิดบั๊กได้ (ฟังก์ชันอาจเผลอแก้ไข
ค่าต้นฉบับโดยไม่ตั้งใจ) — นี่คือจุดที่ **const reference** เข้ามาแก้ปัญหาในหัวข้อถัดไป

## 43.4 const Correctness ตอนที่ 1: `const` กับตัวแปรและ Pointer (Step 340)

ทบทวน Part 9: C มี `const` แต่ Module A–C แทบไม่ได้เน้นเรื่องนี้มากนัก ใน C++ **const
correctness** (การใช้ `const` อย่างถูกต้องและสม่ำเสมอทุกจุดที่ควรใช้) เป็นหลักการสำคัญมากที่
โปรแกรมเมอร์ C++ มืออาชีพยึดถือ เพราะช่วยให้คอมไพเลอร์ช่วยตรวจจับความผิดพลาดแทนเราได้ตั้งแต่
ตอนคอมไพล์ (ทบทวนหลักการ "ให้คอมไพเลอร์ช่วยจับบั๊กแทนที่จะรอเจอตอนรัน" ที่ปรากฏซ้ำๆ ตลอด
หลักสูตรนี้)

### `const` กับตัวแปรธรรมดา

```cpp
const int max_score = 100;  // ค่าคงที่ ห้ามแก้ไขหลังจากนี้
```

เหมือนที่เคยเห็นมาบ้างแล้วใน Part ก่อนๆ — ตัวแปรที่ถูกกำหนดค่าครั้งเดียวแล้วห้ามเปลี่ยนอีก

### `const` กับ Pointer มี 3 แบบที่ต้องแยกให้ออก

นี่คือจุดที่สับสนบ่อยที่สุดสำหรับผู้เริ่มต้น เพราะตำแหน่งของคำว่า `const` เปลี่ยนความหมายไป
โดยสิ้นเชิง:

```cpp
#include <iostream>

int main() {
    int value = 10;
    const int *ptr_to_const = &value;      // pointer to const: แก้ *ptr_to_const ไม่ได้ แต่เปลี่ยน ptr ไปชี้ตัวอื่นได้
    int *const const_ptr = &value;         // const pointer: แก้ *const_ptr ได้ แต่เปลี่ยนให้ชี้ตัวอื่นไม่ได้
    const int *const const_ptr_to_const = &value;  // ทั้งคู่ห้ามแก้

    std::cout << "*ptr_to_const = " << *ptr_to_const << '\n';
    std::cout << "*const_ptr = " << *const_ptr << '\n';
    std::cout << "*const_ptr_to_const = " << *const_ptr_to_const << '\n';

    *const_ptr = 20;  // แก้ค่าที่ const_ptr ชี้ได้ (แค่ตัว pointer เองแก้ไม่ได้)
    std::cout << "หลังแก้ *const_ptr: value = " << value << '\n';

    return 0;
}
```

```
*ptr_to_const = 10
*const_ptr = 10
*const_ptr_to_const = 10
หลังแก้ *const_ptr: value = 20
```

### เทคนิคจำง่าย: "อ่านจากขวาไปซ้าย"

| การประกาศ | อ่านว่า | ความหมาย |
|---|---|---|
| `const int *p` | "p คือ pointer ชี้ไปที่ int ที่เป็น const" | **แก้ค่าที่ p ชี้ไม่ได้** แต่เปลี่ยน p ไปชี้ตัวอื่นได้ |
| `int *const p` | "p คือ const pointer ชี้ไปที่ int" | **เปลี่ยน p ไปชี้ตัวอื่นไม่ได้** แต่แก้ค่าที่ p ชี้ได้ |
| `const int *const p` | "p คือ const pointer ชี้ไปที่ int ที่เป็น const" | **ห้ามแก้ทั้งคู่** ทั้งค่าที่ชี้และตัว pointer เอง |

วิธีจำที่ง่ายที่สุด: **`const` มีผลกับคำที่อยู่ "ทางซ้าย" ของมันเสมอ** (ยกเว้นถ้า `const` อยู่
ซ้ายสุดของประโยค ให้ถือว่ามีผลกับคำแรกที่ตามมา) ลองไล่ดู: `const int *p` → `const` อยู่ซ้ายสุด
มีผลกับ `int` (ค่าที่ชี้เป็น const) ส่วน `int *const p` → `const` อยู่ขวาของ `*` มีผลกับ `*`
(ตัว pointer เองเป็น const)

## 43.5 const Correctness ตอนที่ 2: const Reference Parameter (Step 341)

### ปัญหา: Pass by Value กับข้อมูลขนาดใหญ่สิ้นเปลืองมาก

ทบทวนหัวข้อ 43.3: Pass by Value ปลอดภัย (ฟังก์ชันแก้ไขอะไรก็ไม่กระทบต้นฉบับ) แต่ **มีค่าใช้จ่าย
คือต้อง copy ข้อมูลทั้งก้อนทุกครั้งที่เรียกฟังก์ชัน** ถ้าพารามิเตอร์เป็น `int` (4 ไบต์) แทบไม่มี
ผลกระทบอะไรเลย แต่ถ้าเป็น `std::string` ยาวๆ หรือ `std::vector` ที่มีข้อมูลนับพันตัว การ copy
ทุกครั้งที่เรียกฟังก์ชันจะกลายเป็นค่าใช้จ่ายที่สูงมากโดยไม่จำเป็น:

```cpp
#include <iostream>
#include <string>
#include <vector>

// รับ vector แบบ pass-by-value: ทุกครั้งที่เรียกฟังก์ชันนี้ จะ copy ข้อมูลทั้งก้อนใหม่หมด
long sum_by_value(std::vector<int> numbers) {
    long total = 0;
    for (int n : numbers) {
        total += n;
    }
    return total;
}

// รับแบบ const reference: ไม่มีการ copy เลยแม้แต่ไบต์เดียว แต่ยังคงป้องกันการแก้ไขข้อมูลต้นฉบับ
long sum_by_const_ref(const std::vector<int> &numbers) {
    long total = 0;
    for (int n : numbers) {
        total += n;
    }
    return total;
}

int main() {
    std::vector<int> data(1000, 1);  // vector ขนาด 1000 ตัว ค่าเริ่มต้นทุกตัวเป็น 1

    std::cout << "sum_by_value = " << sum_by_value(data) << '\n';
    std::cout << "sum_by_const_ref = " << sum_by_const_ref(data) << '\n';

    return 0;
}
```

```
sum_by_value = 1000
sum_by_const_ref = 1000
```

ผลลัพธ์เหมือนกันทุกประการ แต่ **`sum_by_value` ต้อง copy ข้อมูลทั้ง 1000 ตัวทุกครั้งที่เรียก**
ในขณะที่ `sum_by_const_ref` **ไม่ copy อะไรเลย** — แค่ส่ง "ชื่อเล่น" ของ `data` เข้าไปเท่านั้น
(รายละเอียดของ `std::vector` จะเจาะลึกใน Part 59 แต่หลักการเรื่อง reference ที่เรียนใน Part นี้
ใช้ได้กับ container ทุกชนิดของ STL เหมือนกันหมด)

### const เข้ามาแก้ปัญหาความปลอดภัยที่ reference ธรรมดาเปิดช่องไว้

การใช้ reference ธรรมดา (`std::vector<int> &numbers` ไม่มี `const`) จะทำให้ **ฟังก์ชันแก้ไข
ข้อมูลต้นฉบับได้ด้วย** ซึ่งถ้าฟังก์ชันแค่ต้องการอ่านค่ามารวม ไม่ได้ตั้งใจแก้ไขอะไรเลย นี่คือช่อง
โหว่ให้เกิดบั๊ก (เผลอแก้ไขข้อมูลผู้เรียกโดยไม่ตั้งใจ) การเติม `const` หน้า reference คือการ
**ประกาศสัญญา (contract) อย่างชัดเจน** ว่า "ฟังก์ชันนี้จะไม่แก้ไขค่านี้เด็ดขาด" — ถ้าเผลอเขียน
โค้ดที่พยายามแก้ไขจริงๆ คอมไพเลอร์จะจับได้ทันที:

```cpp
long bad_modify(const int &n) {
    n = 5;  // ผิด: ห้ามแก้ค่าผ่าน const reference
    return n;
}
```

```
error: assignment of read-only reference 'n'
```

### สรุปกฎทองของหัวข้อนี้

> **กฎการเลือกใช้พารามิเตอร์ฟังก์ชันของหลักสูตรนี้ตั้งแต่ Part นี้เป็นต้นไป**:
> 1. ชนิดข้อมูลพื้นฐานขนาดเล็ก (`int`, `double`, `char`, `bool`) — ใช้ **pass by value** ตามปกติ
>    เพราะ copy ไม่มีค่าใช้จ่ายที่มีนัยสำคัญเลย
> 2. ต้องการให้ฟังก์ชัน**แก้ไข**ค่าต้นฉบับ (เช่น `swap`, การอัปเดต) — ใช้ **reference ธรรมดา**
>    (`T &`)
> 3. ต้องการแค่**อ่าน**ค่าที่มีขนาดใหญ่ (`std::string`, `std::vector`, struct/class ขนาดใหญ่)
>    โดยไม่ต้องการ copy และไม่ต้องการให้แก้ไขได้ — ใช้ **const reference** (`const T &`) เสมอ
>    นี่คือรูปแบบพารามิเตอร์ที่พบบ่อยที่สุดในโค้ด C++ ระดับมืออาชีพ

## 43.6 เกริ่นนำ const Member Function (Step 342)

เมื่อเริ่มเขียน `class` ใน Part 45 เป็นต้นไป จะมีแนวคิดเรื่อง **const member function** —
ฟังก์ชันที่เป็นสมาชิกของ class ที่ประกาศด้วยคำว่า `const` ต่อท้าย signature เพื่อรับประกันว่า
ฟังก์ชันนั้นจะ**ไม่แก้ไขข้อมูลภายใน object เลย**:

```cpp
// ตัวอย่างคร่าวๆ เพื่อให้เห็นภาพ (รายละเอียดเต็มรูปแบบจะเรียนใน Part 45 และ Part 47)
class BankAccount {
public:
    double get_balance() const {  // const ท้ายฟังก์ชัน: รับประกันว่าไม่แก้ไข object เลย
        return balance;
    }
    void deposit(double amount) {  // ไม่มี const เพราะฟังก์ชันนี้ตั้งใจแก้ไข balance
        balance += amount;
    }
private:
    double balance = 0.0;
};
```

ความเชื่อมโยงกับสิ่งที่เรียนใน Part นี้คือหลักการเดียวกันเป๊ะ: `get_balance()` เป็น const
member function ทำให้เรียกใช้ผ่าน **const reference ไปยัง object** ได้อย่างปลอดภัย เช่น
ฟังก์ชันที่รับ `const BankAccount &account` จะสามารถเรียก `account.get_balance()` ได้ (เพราะ
`get_balance` รับประกันว่าไม่แก้ไข) แต่จะเรียก `account.deposit(100)` ไม่ได้เลย (เพราะ
`deposit` ไม่ใช่ const member function อาจแก้ไข object) คอมไพเลอร์จะจับข้อผิดพลาดนี้ให้
อัตโนมัติ — นี่คือพลังที่แท้จริงของ const correctness เมื่อนำไปใช้ร่วมกับ class อย่างสม่ำเสมอ
รายละเอียดทั้งหมดจะกลับมาเจาะลึกอีกครั้งใน **Part 47 (Encapsulation)**

## 43.7 เมื่อไหร่ควรใช้ Pointer เมื่อไหร่ควรใช้ Reference (Step 343)

หลังจากเห็นทั้งจุดเหมือนและจุดต่างแล้ว มาสรุปเป็นแนวทางการตัดสินใจที่ใช้ได้จริงในการออกแบบ
ฟังก์ชันตลอดหลักสูตรที่เหลือ:

| สถานการณ์ | ควรใช้ | เหตุผล |
|---|---|---|
| พารามิเตอร์ที่ **ต้องมีอยู่จริงเสมอ** ไม่มีทาง "ไม่มีค่า" | Reference | Reference รับประกันว่าไม่เป็น null ตามกฎภาษา ไม่ต้องเช็คเลย |
| พารามิเตอร์ที่ **อาจไม่มีค่า** (optional) เช่น "ค้นหาแล้วอาจไม่เจอ" | Pointer (หรือ `std::optional` ที่จะเรียนใน Part 72) | Pointer เป็น `nullptr` ได้ตามธรรมชาติ สื่อความหมาย "ไม่มี" ได้ตรงไปตรงมา |
| ต้องการแก้ไขค่าต้นฉบับที่แน่นอนว่ามีอยู่ | Reference (`T &`) | สั้น กระชับ ไม่ต้องมี `*`/`&` รกโค้ด |
| ต้องการอ่านข้อมูลขนาดใหญ่โดยไม่ copy และไม่แก้ไข | const Reference (`const T &`) | ปลอดภัยและมีประสิทธิภาพสูงสุด (หัวข้อ 43.5) |
| ต้องการเปลี่ยนให้ตัวแปรชี้ไปยังข้อมูลอื่นได้ (reseat) | Pointer | Reference reseat ไม่ได้ตามกฎภาษา (หัวข้อ 43.1) |
| จัดการ array ของ "ตัวชี้ไปยังหลายๆ object" | Pointer | ไม่มี "array of reference" ในภาษา C++ เลย |
| ทำงานกับโครงสร้างข้อมูลที่เชื่อมโยงกัน เช่น Linked List, Tree | Pointer | ต้องมีสถานะ "ไม่มี node ถัดไป" (`nullptr`) ซึ่งเป็นส่วนสำคัญของโครงสร้าง (ทบทวน Part 19, 21) |
| เขียนโค้ดที่ต้องทำงานร่วมกับ C library เดิม (เช่น POSIX API จาก Module C) | Pointer | C ไม่มีแนวคิดเรื่อง reference เลย ฟังก์ชัน C ทุกตัวรับแค่ pointer |

> **หลักการโดยรวม**: ถ้าไม่มีเหตุผลจำเป็นต้องใช้ pointer (optional value, reseat, ทำงานกับ C
> library, โครงสร้างข้อมูลที่เชื่อมโยงกัน) **ให้เลือก reference เป็นค่าเริ่มต้นเสมอ** เพราะ
> ปลอดภัยกว่า อ่านง่ายกว่า และคอมไพเลอร์ช่วยตรวจสอบให้มากกว่า — นี่คือแนวปฏิบัติที่สอดคล้องกับ
> C++ Core Guidelines ที่จะเจาะลึกใน Part 80

## 43.8 Reference เป็นค่าที่ฟังก์ชันคืนกลับมา และอันตรายของมัน (Step 344)

### การคืน Reference ที่ปลอดภัย

ฟังก์ชันสามารถคืนค่าเป็น reference ได้เช่นกัน ทำให้ผู้เรียกสามารถแก้ไขค่าที่ฟังก์ชันคืนมาได้
โดยตรง:

```cpp
#include <iostream>

// คืน reference ไปยัง element ของ array ที่ผู้เรียกส่งเข้ามา (ปลอดภัย เพราะ array มีอยู่จริงที่ผู้เรียก)
int &get_element(int arr[], int index) {
    return arr[index];
}

int main() {
    int scores[5] = {10, 20, 30, 40, 50};

    get_element(scores, 2) = 999;  // แก้ค่าผ่าน reference ที่ได้คืนมาได้โดยตรง

    for (int i = 0; i < 5; i++) {
        std::cout << scores[i] << ' ';
    }
    std::cout << '\n';

    return 0;
}
```

```
10 20 999 40 50
```

สังเกตว่า `get_element(scores, 2) = 999;` **เอาผลลัพธ์ของการเรียกฟังก์ชันมาไว้ฝั่งซ้ายของ `=`
ได้เลย** เพราะฟังก์ชันคืนค่าเป็น reference (ไม่ใช่ค่าธรรมดา) — นี่คือกลไกเดียวกันกับที่
`operator[]` ของ `std::vector`/`std::map` ใช้ ทำให้เขียน `my_vector[0] = 100;` ได้โดยตรง
(จะเห็นเต็มรูปแบบใน Part 51 เรื่อง Operator Overloading)

โค้ดนี้ปลอดภัยเพราะ `arr` เป็น array ที่**มีอยู่จริงที่ผู้เรียก** (`scores` ใน `main`) — ฟังก์ชัน
`get_element` แค่คืน "ชื่อเล่น" ของ element ที่มีอยู่แล้วจริงๆ ไม่ได้สร้างอะไรขึ้นมาใหม่ชั่วคราว
เลย

### อันตรายร้ายแรง: คืน Reference ไปยัง Local Variable

```cpp
/* ⚠️ ตัวอย่างนี้จงใจแสดง Undefined Behavior เพื่อการศึกษา ห้ามเขียนโค้ดแบบนี้จริง */
int &make_dangling_reference() {
    int local_value = 42;   // local_value อยู่บน stack ของฟังก์ชันนี้เท่านั้น
    return local_value;     // อันตราย: คืน reference ไปยังตัวแปรที่กำลังจะถูกทำลาย
}

int main() {
    int &r = make_dangling_reference();
    return r;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 dangling.cpp -o dangling
```

```
warning: reference to local variable 'local_value' returned [-Wreturn-local-addr]
    3 |     return local_value;
      |            ^~~~~~~~~~~
note: declared here
    2 |     int local_value = 42;
```

รันโปรแกรมนี้จริง (แม้จะคอมไพล์ผ่านและมีแค่ Warning ไม่ใช่ Error!) มักจะได้ **Segmentation
Fault** หรือค่าขยะที่คาดเดาไม่ได้ทันที เพราะ `local_value` เป็นตัวแปรที่อยู่บน **stack frame**
ของฟังก์ชัน `make_dangling_reference` (ทบทวน Memory Layout จาก Part 26) เมื่อฟังก์ชันจบการ
ทำงาน stack frame ของมันจะถูกคืนกลับไปให้ระบบใช้ต่อทันที — `local_value` ไม่มีอยู่จริงอีกต่อไป
แล้ว **reference ที่คืนกลับมาจึงกลายเป็น dangling reference** (แนวคิดเดียวกับ Dangling Pointer
ที่เรียนไปแล้วใน Part 11 และ Part 38 เป๊ะ เพียงแต่คราวนี้เกิดกับ reference แทน pointer)

> **เหตุใด compiler ปล่อยให้แค่ Warning ไม่ Error ไปเลย**: ในทางเทคนิค การคืน reference ไปยัง
> local variable ไม่ใช่ Syntax Error — ภาษาอนุญาตให้ทำได้ (compiler ไม่สามารถพิสูจน์ได้ 100%
> ในทุกกรณีที่ซับซ้อนว่านี่คือปัญหาเสมอไป) แต่ **ผลลัพธ์ที่ได้คือ Undefined Behavior เต็มรูปแบบ**
> — ทบทวนแนวคิด UB จาก Part 1: โปรแกรมอาจ crash ทันที อาจได้ค่าขยะ หรือแม้แต่ **อาจดูเหมือน
> ทำงานถูกต้องในบางครั้ง** (ถ้าหน่วยความจำตรงนั้นบังเอิญยังไม่ถูกเขียนทับ) ซึ่งอันตรายที่สุดเพราะ
> ทำให้เข้าใจผิดว่าโค้ดถูกต้อง

### กฎทองของหัวข้อนี้

> **ห้ามคืน reference ไปยัง local variable ของฟังก์ชันเด็ดขาด** กฎการตรวจสอบง่ายๆ ที่ใช้ได้
> เสมอ: ก่อนเขียน `return` ของฟังก์ชันที่คืน reference ให้ถามตัวเองว่า **"สิ่งที่กำลังจะคืนกลับ
> ไปนี้ ยังจะมีอยู่จริงหลังจากฟังก์ชันนี้จบการทำงานหรือไม่?"** ถ้าคำตอบคือ "ไม่" (เช่นเป็นตัวแปร
> local ธรรมดา) **ห้ามคืนเป็น reference เด็ดขาด** ให้คืนเป็นค่าธรรมดา (`T` ไม่ใช่ `T&`) แทน
> การคืนที่ปลอดภัย (แบบ `get_element` ในตัวอย่างก่อนหน้า) ต้องเป็นการคืน reference ไปยังสิ่งที่
> **มีอยู่แล้วก่อนฟังก์ชันถูกเรียก** เช่น argument ที่ผู้เรียกส่งเข้ามา หรือข้อมูลที่อยู่ใน
> object ที่ผู้เรียกเป็นเจ้าของอยู่แล้ว (จะกลับมาเจาะลึกเรื่องนี้อีกครั้งเมื่อเขียน const member
> function ที่คืน reference ไปยัง field ภายใน class ใน Part 47 และเรื่อง Move Semantics ที่
> เกี่ยวข้องกับ lifetime ของค่าใน Part 70)

## ข้อผิดพลาดที่พบบ่อย (Common Pitfalls)

1. **ลืม initialize reference ตอนประกาศ** — `int &r;` โดยไม่มีค่าเริ่มต้นจะ Error ทันที ต่างจาก
   pointer ที่ประกาศลอยๆ ก่อนได้ (แม้จะไม่ใช่ style ที่ดีก็ตาม)
2. **เข้าใจผิดว่า `ref = other_var;` ทำให้ reference ไปผูกกับตัวแปรอื่น** — ในความเป็นจริงมันคือ
   การ assign ค่าของ `other_var` ใส่ตัวแปรที่ `ref` ผูกอยู่เดิม (ทบทวนหัวข้อ 43.1 เรื่อง reseat
   ไม่ได้)
3. **ใช้ reference ธรรมดาแทนที่จะเป็น const reference สำหรับพารามิเตอร์ที่แค่ต้องการอ่าน** —
   เปิดช่องให้ฟังก์ชันเผลอแก้ไขข้อมูลต้นฉบับโดยไม่ตั้งใจ ควรใส่ `const` เสมอเมื่อไม่ต้องการแก้ไข
4. **คืน reference ไปยัง local variable** — คอมไพล์ผ่านได้ (บาง compiler แค่ Warning) แต่เป็น
   Undefined Behavior เต็มรูปแบบเมื่อรันจริง (ทบทวนหัวข้อ 43.8) ให้ตรวจสอบทุกครั้งว่าสิ่งที่คืน
   กลับไปยังมีชีวิตอยู่หลังฟังก์ชันจบทำงานหรือไม่
5. **สับสนอ่านตำแหน่งของ `const` ใน pointer declaration ผิด** — `const int *p` กับ `int
   *const p` มีความหมายต่างกันโดยสิ้นเชิง ใช้เทคนิค "อ่านจากขวาไปซ้าย" ที่อธิบายในหัวข้อ 43.4
   ช่วยแยกแยะ
6. **พยายามสร้าง "array of reference"** — เช่น `int &arr[5];` ภาษา C++ ไม่อนุญาตให้ทำแบบนี้
   เด็ดขาด (ทบทวนตารางในหัวข้อ 43.2) ถ้าต้องการ array ของสิ่งที่ "ชี้ไปยังตัวแปรอื่น" ต้องใช้
   pointer (`int *arr[5];`) แทน

## แบบฝึกหัดท้ายบท

1. เขียนฟังก์ชัน `void increase_by_percent(double &value, double percent)` ที่เพิ่มค่า
   `value` ขึ้นตามเปอร์เซ็นต์ที่กำหนดผ่าน reference แล้วเขียน `main` ที่เรียกใช้กับราคาสินค้า
   หลายๆ ตัวใน array
2. เขียนฟังก์ชัน `long total_length(const std::vector<std::string> &names)` ที่คำนวณความยาว
   รวมของ string ทุกตัวใน vector โดยต้องรับพารามิเตอร์แบบ const reference เท่านั้น (ห้ามใช้
   pass by value)
3. เขียนโปรแกรมที่ประกาศ pointer ทั้ง 3 แบบตามหัวข้อ 43.4 (`const int *`, `int *const`,
   `const int *const`) แล้วลองเขียนโค้ดที่พยายามแก้ไขแต่ละแบบ ระบุว่าอันไหนคอมไพล์ผ่านและอันไหน
   Error พร้อมอธิบายเหตุผล
4. เขียนฟังก์ชัน `int &get_max(int arr[], int n)` ที่คืน reference ไปยัง element ที่มีค่ามาก
   ที่สุดใน array แล้วใช้ reference ที่คืนมาแก้ไขค่านั้นโดยตรงจาก `main`
5. อธิบายด้วยคำพูดตัวเอง (เขียนเป็นคอมเมนต์) ว่าทำไมฟังก์ชันที่คืน reference ไปยังตัวแปร local
   ถึงเป็นอันตราย จากนั้นแก้ไขฟังก์ชันในหัวข้อ 43.8 ให้ปลอดภัยโดยเปลี่ยนชนิดคืนค่าจาก `int &`
   เป็น `int` ธรรมดา
6. ให้พิจารณาสถานการณ์ 3 แบบต่อไปนี้ แล้วเลือกว่าควรใช้ pointer หรือ reference พร้อมให้เหตุผล:
   (ก) ฟังก์ชันค้นหาตัวเลขใน array ที่อาจไม่พบเลย, (ข) ฟังก์ชันที่รับ `struct Point` ขนาดใหญ่
   มาแค่อ่านค่าพิกัด, (ค) ฟังก์ชันที่เพิ่ม node ใหม่เข้าไปใน Linked List (ทบทวนจาก Part 19)

### แนวทางเฉลยข้อ 1

```cpp
#include <iostream>

void increase_by_percent(double &value, double percent) {
    value = value + (value * percent / 100.0);
}

int main() {
    double prices[4] = {100.0, 250.0, 80.0, 500.0};

    for (int i = 0; i < 4; i++) {
        increase_by_percent(prices[i], 10.0);  // ขึ้นราคาทุกตัว 10%
    }

    for (int i = 0; i < 4; i++) {
        std::cout << "ราคาใหม่: " << prices[i] << '\n';
    }

    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 increase_percent.cpp -o increase_percent
./increase_percent
```

```
ราคาใหม่: 110
ราคาใหม่: 275
ราคาใหม่: 88
ราคาใหม่: 550
```

จุดสำคัญ: พารามิเตอร์ `value` เป็น reference ธรรมดา (ไม่ใช่ const) เพราะฟังก์ชันนี้**ตั้งใจแก้ไข**
ค่าต้นฉบับโดยตรงตามหลักการที่เรียนในหัวข้อ 43.3 — ถ้าใช้ pass by value ธรรมดาแทน ฟังก์ชันจะแก้ไข
แค่สำเนาที่ copy เข้ามา ราคาใน array ของ `main` จะไม่เปลี่ยนแปลงเลยแม้แต่ตัวเดียว

### แนวทางเฉลยข้อ 3

```cpp
#include <iostream>

int main() {
    int a = 1;
    int b = 2;

    const int *p1 = &a;   // pointer to const
    p1 = &b;              // OK: เปลี่ยนให้ p1 ไปชี้ b ได้ (ตัว pointer ไม่ใช่ const)
    // *p1 = 99;          // ผิดถ้าเปิดบรรทัดนี้: ห้ามแก้ค่าที่ p1 ชี้

    int *const p2 = &a;   // const pointer
    *p2 = 99;             // OK: แก้ค่าที่ p2 ชี้ได้ (แค่ตัว pointer ห้ามเปลี่ยน)
    // p2 = &b;           // ผิดถ้าเปิดบรรทัดนี้: ห้ามเปลี่ยนให้ p2 ไปชี้ตัวอื่น

    const int *const p3 = &a;  // const pointer to const
    // *p3 = 99;          // ผิดถ้าเปิดบรรทัดนี้: ห้ามแก้ค่า
    // p3 = &b;           // ผิดถ้าเปิดบรรทัดนี้: ห้ามเปลี่ยนให้ชี้ตัวอื่น

    std::cout << "*p1 = " << *p1 << '\n';
    std::cout << "a (หลัง *p2 = 99) = " << a << '\n';
    std::cout << "*p3 = " << *p3 << '\n';

    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 const_pointer_variants.cpp -o const_pointer_variants
./const_pointer_variants
```

```
*p1 = 2
a (หลัง *p2 = 99) = 99
*p3 = 99
```

คำอธิบายทีละตัวตามที่โจทย์ขอ:

- **`p1` (pointer to const)**: บรรทัด `p1 = &b;` คอมไพล์ผ่านสบายๆ เพราะ `const` มีผลกับ**ค่าที่
  p1 ชี้** เท่านั้น ไม่ใช่ตัว `p1` เอง — แต่ถ้าเปิดบรรทัด `*p1 = 99;` จะ Error ทันทีเพราะพยายาม
  แก้ค่าที่เป็น const
- **`p2` (const pointer)**: บรรทัด `*p2 = 99;` คอมไพล์ผ่านเพราะ **ค่าที่ p2 ชี้ไม่ใช่ const**
  แต่ถ้าเปิดบรรทัด `p2 = &b;` จะ Error ทันทีเพราะพยายามเปลี่ยนตัว pointer เองซึ่งเป็น const
- **`p3` (const pointer to const)**: ทั้งสองบรรทัดที่คอมเมนต์ไว้จะ Error ทั้งคู่ถ้าเปิดใช้งาน
  เพราะ `p3` ถูกล็อกทั้งค่าที่ชี้และตัว pointer เองพร้อมกัน

### แนวทางเฉลยข้อ 4

```cpp
#include <iostream>

int &get_max(int arr[], int n) {
    int max_index = 0;
    for (int i = 1; i < n; i++) {
        if (arr[i] > arr[max_index]) {
            max_index = i;
        }
    }
    return arr[max_index];
}

int main() {
    int scores[5] = {70, 95, 60, 88, 92};

    std::cout << "คะแนนสูงสุดก่อนแก้: " << get_max(scores, 5) << '\n';

    get_max(scores, 5) = 100;  // แก้ค่าคะแนนสูงสุดโดยตรงผ่าน reference ที่ฟังก์ชันคืนมา

    std::cout << "คะแนนทั้งหมดหลังแก้: ";
    for (int i = 0; i < 5; i++) {
        std::cout << scores[i] << ' ';
    }
    std::cout << '\n';

    return 0;
}
```

```bash
g++ -Wall -Wextra -Wpedantic -std=c++17 get_max_ref.cpp -o get_max_ref
./get_max_ref
```

```
คะแนนสูงสุดก่อนแก้: 95
คะแนนทั้งหมดหลังแก้: 70 100 60 88 92
```

จุดสำคัญของเฉลยนี้คือฟังก์ชัน `get_max` **ปลอดภัย** ที่จะคืนเป็น reference เพราะ `arr[max_
index]` เป็น element ของ array `scores` ที่มีอยู่จริงใน `main` (ผู้เรียก) ไม่ใช่ตัวแปร local
ของฟังก์ชัน `get_max` เอง — ตรงตามกฎทองในหัวข้อ 43.8: "สิ่งที่คืนกลับไปต้องมีอยู่จริงหลังฟังก์ชัน
จบทำงานด้วย" คำสั่ง `get_max(scores, 5) = 100;` จึงสามารถแก้ไขค่าใน `scores` ได้โดยตรงอย่าง
ปลอดภัย ผลลัพธ์คือตำแหน่งที่มีค่ามากที่สุด (index 1 ซึ่งเดิมคือ 95) ถูกเปลี่ยนเป็น 100

## สรุปท้ายบท

ใน Part นี้เราได้:

- เข้าใจว่า **Reference** คือ "ชื่อเล่น" ของตัวแปรที่มีอยู่แล้ว ไม่ใช่ตัวแปรใหม่ พร้อมกฎเหล็ก 3
  ข้อ: ต้อง initialize ทันที, ไม่มี null reference, และ reseat ไปผูกกับตัวแปรอื่นไม่ได้
- เปรียบเทียบ Reference กับ Pointer ได้อย่างละเอียดครบทุกมิติ ทั้งพฤติกรรมทางภาษาและการใช้งาน
  จริง
- ใช้ Reference เป็นพารามิเตอร์ฟังก์ชัน (Pass by Reference) แก้ปัญหาที่ต้องพึ่ง pointer ใน C
  ได้อย่างกระชับกว่าเดิมมาก และเข้าใจคำตอบเต็มรูปแบบว่าทำไม `std::cin >> a` ไม่ต้องใช้ `&`
- เข้าใจ const correctness อย่างละเอียด ทั้ง const variable, pointer-to-const, const-pointer,
  และที่สำคัญที่สุดคือ **const reference parameter** ซึ่งเป็นรูปแบบพารามิเตอร์ที่ปลอดภัยและมี
  ประสิทธิภาพสูงสุดสำหรับข้อมูลขนาดใหญ่
- เกริ่นนำแนวคิด const member function ที่จะเจาะลึกเมื่อเริ่มเขียน class ใน Part 47
- มีแนวทางตัดสินใจที่ชัดเจนว่าเมื่อไหร่ควรใช้ pointer เมื่อไหร่ควรใช้ reference ในการออกแบบ
  ฟังก์ชันแต่ละแบบ
- เขียนฟังก์ชันที่คืนค่าเป็น reference ได้อย่างปลอดภัย และเข้าใจอันตรายร้ายแรงของการคืน
  reference ไปยัง local variable ซึ่งเป็น Undefined Behavior ที่คอมไพเลอร์เตือนได้แค่บางส่วน
  เท่านั้น
